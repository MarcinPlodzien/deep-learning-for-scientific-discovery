Lab 008 — Analysing a neural network

This notebook is about looking at a network: what can be measured about it before, during and after training, and what these measurements tell us. All quantities are computed with a few lines of PyTorch and plotted with Matplotlib.

We start with the architecture alone (Section 1): a drawing, a table of the layers, the number of parameters and how it grows with width and depth, trainable and frozen parameters, memory and computational cost, and finally the same information obtained with the ready-made tools torchinfo and torchview. Section 2 examines the network before training, layer by layer: its weights, its activations and how many of its nodes are saturated, and the gradients that the first optimisation step would use, together with the role of the initialisation scale. Section 3 follows the network during training, through the losses on the training and validation sets and through the gradients and weight changes of every layer. These curves show when the network begins to overfit, and Section 4 uses the validation set to choose the epoch at which training should have stopped. The chosen model is evaluated once on the test set in Section 5, and Section 6 collects all characteristics of a model in one table. A summary (Section 7) and exercises with solutions (Section 8) close the notebook.

Methods for interpreting what a network has learned (e.g. class activation maps for images) need convolutional networks and are discussed in later classes.

Two functions from the previous notebook are needed throughout: make_mlp builds a dense network from a list of layer sizes, and draw_network draws it.

Code 
def make_mlp(layer_sizes, activation=nn.Tanh):
    """Dense network with the given layer sizes; `activation` after every hidden layer, none after the output layer."""
    layers = []
    for i in range(len(layer_sizes) - 1):
        layers.append(nn.Linear(layer_sizes[i], layer_sizes[i + 1]))
        if i < len(layer_sizes) - 2:
            layers.append(activation())
    return nn.Sequential(*layers)

The drawing function is the same as in the previous notebook. linear_sizes reads the layer sizes from the nn.Linear layers of a model, so that every drawing shows the network that was built, and dense_parameter_count gives the number of parameters for these sizes.

Code 
def draw_network(layer_sizes, activations=None, title="", max_nodes=10, ax=None,
                 input_labels=None, output_labels=None):
    """
    Draw a fully connected network.
    layer_sizes : e.g. [1, 8, 1] = 1 input, one hidden layer with 8 nodes, 1 output
    activations : names of the activation functions of the hidden layers, e.g. ["tanh"]
    max_nodes   : larger layers are drawn with max_nodes nodes and a vertical "..." in the middle
    input_labels, output_labels : optional texts written next to the input and output nodes, e.g. ["$x$"]
    """
    if ax is None:
        fig, ax = plt.subplots(figsize=(1.9 * len(layer_sizes) + 1, 4.2))
    n_layers = len(layer_sizes)
    positions = []                                   # list of (x, y) arrays, one per layer
    for i, n in enumerate(layer_sizes):
        shown = min(n, max_nodes)
        y = np.linspace(-1, 1, shown) if shown > 1 else np.array([0.0])
        positions.append((np.full(shown, float(i)), y * min(1.0, shown / max_nodes + 0.15)))
    # connections between neighbouring layers
    for i in range(n_layers - 1):
        (x0, y0), (x1, y1) = positions[i], positions[i + 1]
        for a in y0:
            for b in y1:
                ax.plot([x0[0], x1[0]], [a, b], color="0.7", lw=0.6, zorder=1)
    # nodes and labels
    for i, (n, (xs, ys)) in enumerate(zip(layer_sizes, positions)):
        if i == 0:
            color, name = "C2", "input"
        elif i == n_layers - 1:
            color, name = "C3", "output"
        else:
            act = activations[i - 1] if activations is not None else ""
            color, name = "C0", f"hidden {i}" + (f"\n{act}" if act else "")
        ax.scatter(xs, ys, s=260, color=color, edgecolor="k", zorder=3)
        if n > max_nodes:                            # mark omitted nodes
            ax.text(xs[0] + 0.2, 0.0, "...", rotation=90, fontsize=14, va="center", ha="center",
                    bbox=dict(facecolor="white", edgecolor="none", pad=1), zorder=4)
        ax.text(xs[0], -1.35, f"{name}\n{n} node" + ("s" if n > 1 else ""), ha="center", va="top", fontsize=10)
    if input_labels is not None:
        for y, lab in zip(positions[0][1], input_labels):
            ax.text(-0.18, y, lab, ha="right", va="center", fontsize=12)
    if output_labels is not None:
        for y, lab in zip(positions[-1][1], output_labels):
            ax.text(n_layers - 1 + 0.18, y, lab, ha="left", va="center", fontsize=12)
    n_params = sum(n_in * n_out + n_out for n_in, n_out in zip(layer_sizes[:-1], layer_sizes[1:]))
    ax.set_title((title + "\n" if title else "") + f"layer sizes {layer_sizes},  {n_params} parameters", fontsize=11)
    ax.set_xlim(-0.8, n_layers - 0.2); ax.set_ylim(-2.1, 1.3)
    ax.axis("off")
    return ax

def linear_sizes(model):
    """Layer sizes [n_0, n_1, ..., n_L] of a dense network, read from its nn.Linear layers in the order of definition."""
    linear = [m for m in model.modules() if isinstance(m, nn.Linear)]
    return [linear[0].in_features] + [m.out_features for m in linear]

def dense_parameter_count(sizes):
    """Number of weights and biases of a dense network with these layer sizes."""
    return sum(n_out * (n_in + 1) for n_in, n_out in zip(sizes[:-1], sizes[1:]))

1. The architecture

1.1 Drawing of the network

The network analysed in this notebook has layer sizes \([1, 64, 64, 64, 1]\) with \(\tanh\) activations: one input, three hidden layers of 64 nodes, one output.

It is deliberately much larger than the 30 training points of Section 2 require (8513 parameters, counted in Section 1.3), so that it is able to overfit them (Section 4). Three hidden layers make the effects of depth on activations and gradients visible. \(\tanh\) is used because for it “saturated” has a simple meaning (Section 2.3). The width 64 itself is arbitrary: with widths 32 and 128 the same training run also shows a minimum of the validation loss followed by a rise.

1.2 A table of the layers

We pass a small batch through the layers one by one and record, for each layer, its type, the shapes of its input and output, the shapes of its parameters, and the number of parameters. A pandas.DataFrame is a convenient container for such a table.

An nn.Sequential behaves like a list of layers: for layer in model runs over them in order, and model[0], model[-1] select the first and the last layer. In the table, index is the position of the module in the Sequential; it is not the layer index \(l\) of Section 1.3. type(layer).__name__ gives the name of the class of an object as a string (e.g. 'Linear'), and p.numel() the number of entries of a tensor.

Code 
def layer_table(model, x):
    """One row per layer of an nn.Sequential model, for the input batch x."""
    rows = []
    for i, layer in enumerate(model):
        x_in = x
        x = layer(x)                                            # pass the batch through this layer
        params = list(layer.parameters())
        rows.append({
            "index": i,
            "layer": type(layer).__name__,
            "input shape": tuple(x_in.shape),
            "output shape": tuple(x.shape),
            "parameter shapes": [tuple(p.shape) for p in params],
            "parameters": sum(p.numel() for p in params),
            "trainable": sum(p.numel() for p in params if p.requires_grad),
        })
    return pd.DataFrame(rows)

1.3 Counting parameters

The layers are numbered from 0 to \(L\), with \(n_0\) the number of inputs and \(n_L\) the number of outputs; for \([1, 64, 64, 64, 1]\) the sizes \(n_0\) and \(n_4\) are 1 and the hidden sizes \(n_1, n_2, n_3\) are 64. The Linear layer from layer \(l-1\) to layer \(l\) has \(n_l n_{l-1}\) weights and \(n_l\) biases, \[n_l n_{l-1} + n_l = n_l(n_{l-1}+1) \tag{1}\] parameters. The total from the table is compared with \[P = \sum_{l=1}^{L} n_l\,(n_{l-1}+1) \tag{2}\] and with PyTorch’s own count.

1.4 Number of parameters against width and depth

For a network \([1, W, \dots, W, 1]\) with \(D\) hidden layers of width \(W\) the count is \[P(W, D) = W(1+1) + (D-1)\,W(W+1) + (W+1) . \tag{3}\] The three terms are the first layer (\(W\) weights and \(W\) biases), the \(D-1\) layers from width \(W\) to width \(W\) (\(W^2\) weights and \(W\) biases each) and the output layer (\(W\) weights and one bias). The count is therefore linear in the depth \(D\) and, for two or more hidden layers, quadratic in the width \(W\). On the log-log axes below a power law \(W^k\) is a straight line of slope \(k\).

Code 
widths = np.array([4, 8, 16, 32, 64, 128, 256])
fig, ax = plt.subplots(figsize=(7, 4.5))
for depth in [1, 2, 3, 5]:
    counts = [sum(p.numel() for p in make_mlp([1] + [w] * depth + [1]).parameters()) for w in widths]
    ax.loglog(widths, counts, "o-", label=f"{depth} hidden layer" + ("s" if depth > 1 else ""))
ax.loglog(widths, 3 * widths**2, "k:", label=r"$\propto W^2$")    # only the slope 2 matters; the factor 3 places the line near the data
ax.set_xlabel("width $W$ (nodes per hidden layer)"); ax.set_ylabel("number of parameters"); ax.legend()
plt.show()

With one hidden layer the count grows only linearly (\(3W+1\)); every additional hidden layer adds a \(W\times W\) matrix, so the deeper networks follow the \(W^2\) line.

1.5 Trainable and frozen parameters

Setting requires_grad = False for a parameter freezes it: no gradient is computed for it, and an optimiser leaves it unchanged. Freezing is used, for example, when a pretrained part of a network is kept fixed. Freezing the first layer of a copy of the model changes the count of trainable parameters as follows.

The copy must be made with copy.deepcopy. A plain assignment frozen_model = model only gives a second name to the same network, and a shallow copy.copy(model) creates a new container that still holds the same parameter tensors: freezing it would freeze model as well. copy.deepcopy duplicates every parameter.

Code 
frozen_model = copy.deepcopy(model)              # an independent copy, so that `model` itself stays unchanged
for p in frozen_model[0].parameters():           # module 0 of the `Sequential`, i.e. the first `Linear` layer
    p.requires_grad = False

trainable = sum(p.numel() for p in frozen_model.parameters() if p.requires_grad)
total = sum(p.numel() for p in frozen_model.parameters())
print(f"total parameters: {total},  trainable: {trainable},  frozen: {total - trainable}  (= 64 weights + 64 biases of the first Linear layer)")
total parameters: 8513,  trainable: 8385,  frozen: 128  (= 64 weights + 64 biases of the first Linear layer)

1.6 Memory and computational cost

Every parameter is stored as a float32 number of 4 bytes. One forward pass for one input needs, in every Linear layer, \(n_{\rm in}\,n_{\rm out}\) multiplications and as many additions (a multiply-add per weight). These numbers set the scale for large networks: a model with \(10^9\) parameters needs 4 GB only to store its weights.

The count of multiply-adds includes only the multiplications by weights; the bias additions and the activations add about \(n_{\rm out}\) operations per layer, which is small compared with \(n_{\rm in}n_{\rm out}\) for wide layers. In the printout 1 kB is taken as 1024 bytes.

Code 
n_bytes = sum(p.numel() * p.element_size() for p in model.parameters())     # element_size() = bytes per number
mult_adds = sum(n_in * n_out for n_in, n_out in zip(layer_sizes[:-1], layer_sizes[1:]))
print(f"memory of the parameters: {n_bytes} bytes = {n_bytes / 1024:.1f} kB")
print(f"multiply-adds per input sample in one forward pass: {mult_adds}")
memory of the parameters: 34052 bytes = 33.3 kB
multiply-adds per input sample in one forward pass: 8320

1.7 Ready-made tools

Everything in Sections 1.1–1.6 was computed directly from the definitions, because this shows what each number means. In practice the same information is obtained with ready-made tools. PyTorch itself offers basic pieces (print(model), parameters(), requires_grad, modules(), and the operation counter FlopCounterMode from torch.utils.flop_counter, which counts the floating-point operations of a computation). A table of the layers and a drawing come from two small additional packages. The function torchinfo.summary of the package torchinfo prints a table of the layers with output shapes and parameter counts, the numbers of trainable and frozen parameters, and estimates of memory and cost. The package torchview draws the network as a graph of layers and tensor shapes; it uses the program Graphviz, which is installed in Colab.

The two packages are not part of Colab’s standard installation. %pip install installs Python packages from inside a notebook into the Python environment that runs the notebook (-q: print less); it takes a few seconds and is needed once per Colab session. The note printed by %pip about restarting the kernel concerns packages that were already imported before the installation; torchinfo and torchview are imported only after it, so no restart is needed.

The tools are faster to use, and they are the right choice for large models. The torchinfo table is the quickest check of shapes and parameter counts; the torchview graph shows how the layers are connected, which matters once the data flow is not a single chain (skip connections, several inputs). The direct computations of Sections 1.1–1.6 remain useful: they show what the numbers mean, and they can be extended to any quantity a tool does not provide (e.g. the saturation of the activations in Section 2.3).

2. The network before training

2.1 Damped-oscillation data

The data are noisy measurements of a damped oscillation \[y(t) = e^{-0.2t}\cos(2t), \qquad t\in[0, 10], \tag{7}\] with noise of standard deviation \(\sigma\), 0.1, and deliberately few training points, so that overfitting (Section 4) becomes visible: 30 points for training, 40 for validation, 40 for testing. The input is rescaled to \([-1, 1]\).

The numbers are chosen for this purpose. The noise \(0.1\) is about 10% of the amplitude of the signal, which starts at 1: large enough for overfitting to be visible, small enough for the oscillation to remain recognisable. With only 30 training points the network of Section 1 (8513 parameters) can memorise the training set. The validation and test sets are larger (40 points each) because their losses are used to choose and to evaluate the model, and a larger set gives a less noisy estimate. The positions \(t\) are drawn uniformly at random, so the three sets cover the interval in the same way; all 110 points are drawn at once, and the first 30, the next 40 and the last 40 form the three sets.

Besides the data, the cell creates t_plot (400 equally spaced values) and the corresponding network input X_plot. These are not data: they are a dense grid on which functions are evaluated for plotting, and on which the hidden layers are examined in Section 2.3. The rescaling \[t \;\to\; t/5 - 1 \tag{8}\] maps \([0, 10]\) onto \([-1, 1]\). \(\tanh\) changes only for arguments of order one; with the raw inputs (up to 10) and first-layer weights in \([-1, 1]\), 52% of the first-layer activations of the untrained network would be saturated (Section 2.3), with the rescaled inputs below 0.1%.

2.2 Initial weights

PyTorch initialises the weights of nn.Linear(n_in, n_out) uniformly in \([-1/\sqrt{n_{\rm in}},\ 1/\sqrt{n_{\rm in}}]\). The first layer (one input) therefore has weights in \([-1, 1]\), the hidden layers (64 inputs) in \([-0.125, 0.125]\). The histograms below show the weights of every Linear layer of the untrained model, with these bounds as dashed lines. The biases are drawn from the same interval.

The scale \(1/\sqrt{n_{\rm in}}\) keeps the size of the weighted sum \[s = \sum_{i=1}^{n_{\rm in}} w_i x_i \tag{9}\] independent of the number of inputs: for independent \(w_i\) and \(x_i\) with zero mean \[{\rm Var}(s) = n_{\rm in}\,{\rm Var}(w)\,{\rm Var}(x), \tag{10}\] which does not grow with \(n_{\rm in}\) when \[{\rm Var}(w)\propto 1/n_{\rm in} . \tag{11}\]

2.3 Activations and saturated nodes

The 400 inputs of the dense grid X_plot are passed through the network, and the output of every activation layer is recorded. A node computes \(\tanh\) of its weighted input \(z\), \[h = \tanh z, \qquad \frac{dh}{dz} = 1 - \tanh^2 z = 1 - h^2 . \tag{12}\] A node is saturated when \[|h| > 0.95, \qquad\text{so that}\qquad \frac{dh}{dz} = 1-h^2 < 0.0975 \approx 0.1 : \tag{13}\] its derivative is small, so gradients passing through it are damped by a factor of ten or more. The threshold 0.95 is a convention; any value between about 0.9 and 0.99 gives the same qualitative picture. The saturated fraction of a layer, shown in the panel titles below, is the fraction of activation values \(h\) (over all nodes and all 400 inputs) that satisfy the condition (13).

Code 
def hidden_activations(model, x):
    """Outputs of all activation layers of an nn.Sequential model for the input batch x."""
    outputs = []
    with torch.no_grad():
        for layer in model:
            x = layer(x)
            if not isinstance(layer, nn.Linear):     # keep the outputs of the activation layers only
                outputs.append(x.numpy().copy())   # .numpy() shares memory with the tensor; copy() makes the stored array independent
    return outputs

2.4 Gradients in every layer

One forward and one backward pass on the training set give the gradient of the loss with respect to every weight matrix. Its norm tells how strongly each layer would be changed by the first step of gradient descent.

model.zero_grad() first sets the stored gradients to zero, because PyTorch adds new gradients to those already in .grad. nn.functional.mse_loss(a, b) is the function form of nn.MSELoss()(a, b) and gives the same value. For a matrix, .norm() is the Frobenius norm \[\|g\| = \sqrt{\sum_{ij} g_{ij}^2} , \tag{14}\] the length of the matrix viewed as one long vector.

Code 
def gradient_norms(model, X, Y):
    """Norm of dL/dW for the weight matrix of every Linear layer (one backward pass)."""
    model.zero_grad()
    nn.functional.mse_loss(model(X), Y).backward()
    return [layer.weight.grad.norm().item() for layer in model if isinstance(layer, nn.Linear)]

2.5 The influence of the initialisation scale

The analysis of Sections 2.3–2.4 is repeated for a deeper network (6 hidden layers of width 64) whose weights are drawn from \(\mathcal N(0, (c/\sqrt{n_{\rm in}})^2)\), the normal (Gaussian) distribution with mean 0 and standard deviation \(c/\sqrt{n_{\rm in}}\), for three values of \(c\). The table lists, for every hidden layer, the standard deviation of the activations and the fraction of saturated nodes, and the gradient norm of every weight matrix.

The three values stand for a too small, a standard and a too large scale. Their effect is multiplied once per layer, so a network deeper than that of Section 1 makes it easier to see. A normal distribution is used instead of PyTorch’s uniform one, because only the standard deviation matters for the argument. For comparison, the default uniform distribution on \([-1/\sqrt{n_{\rm in}}, 1/\sqrt{n_{\rm in}}]\) has standard deviation \(1/\sqrt{3n_{\rm in}}\), which corresponds to \[c = 1/\sqrt3 \approx 0.58 ; \tag{15}\] this is why the activations of Section 2.3 shrink with depth.

In the code, the functions of nn.init overwrite the values of an existing tensor in place (in PyTorch a trailing underscore, as in normal_, marks an in-place operation), and the biases are set to zero so that only the weight scale is varied. The activations are measured on the dense grid X_plot, which samples the input interval evenly; the gradients are those of the training loss and need the training data. Finally, pivot rearranges the long table (one row per pair (\(c\), layer)) into a wide one with one row per layer and one column per quantity and value of \(c\), so that the three values of \(c\) stand side by side; round(4) only affects the display.

For the smallest scale, \(c\) of 0.5, the activations shrink by about a factor of two per layer, and all gradients are more than twenty times smaller than for the standard scale 1, decreasing slightly towards the first layers: the signal fades in both directions (vanishing gradients). For the standard scale the activations decrease with depth only slowly (for \(\tanh\) the derivative is below 1, so this scale does not exactly preserve the signal), and the gradients are of similar size in hidden layers 2–6 (layer 1 has only 64 weights, so its norm is smaller; see Section 2.4). For the largest scale, 3, a large fraction of the nodes (up to about half in the deeper layers) is saturated, and the gradients are tens of times larger than for the standard scale: the first optimisation steps would be very large (exploding gradients).

The weight scale therefore has to be chosen with the depth and the activation in mind; standard choices are derived from such arguments. Xavier (Glorot) initialisation uses \[{\rm Var}(w) = \frac{2}{n_{\rm in}+n_{\rm out}} , \tag{16}\] a scale \(c\) of 1 for square layers, and is meant for \(\tanh\)-like activations. He initialisation uses \[{\rm Var}(w) = \frac{2}{n_{\rm in}} , \tag{17}\] a scale \(c\) of \(\sqrt2\), which compensates for the rectified linear unit (ReLU), \[\mathrm{ReLU}(z)=\max(0,z) , \tag{18}\] which sets negative inputs (about half of them) to zero.

3. Monitoring training

The training function below is a standard training loop (full batch, Adam) with additional bookkeeping. After every epoch it records the training loss and the validation loss, the norm of the gradient of every weight matrix, and the relative change of every weight matrix since the start, \(\|W(e) - W(0)\| / \|W(0)\|\), where \(e\) is the epoch. It also keeps a copy of the parameters at the epoch with the smallest validation loss so far, which Section 4 uses.

The record log is a dictionary of lists, with one entry appended per epoch. For the gradients and weight changes each entry is a list of 4 numbers (one per Linear layer); at the end np.array turns this list of lists into an array of shape (number of epochs, 4), so that log["grad"][:, k] is the history of layer \(k+1\). The 30 training points form one batch, so every epoch is a single exact gradient step and the loss curves contain no noise from a random choice of mini-batches.

The learning rate lr=1e-2 is a common starting value for Adam on small problems; it was not tuned. With learning rates \(10^{-3}\), \(3\cdot10^{-3}\), \(10^{-2}\) and \(3\cdot10^{-2}\) the smallest validation loss is reached at epochs 753, 419, 293 and 281, and in every case the validation loss rises afterwards. The 3000 epochs are far more than needed to reach the minimum, so that the overfitting after it can be seen.

Three copies in the code protect stored values from later changes. In W0 = [... .detach().clone() ...] the clone() is needed because optimizer.step() changes the weights in place: without it the list would hold the current weight tensors themselves and the relative change would always be zero, while detach() keeps the copy out of the gradient computation. The record best = {"val": np.inf, ...} starts from infinity, so the validation loss of the first epoch is always smaller and becomes the first “best” model. Its parameters are stored with copy.deepcopy(model.state_dict()), because state_dict() returns a dictionary of the parameter tensors themselves, not of copies; without deepcopy the stored “best” state would follow every later optimiser step and end up equal to the final parameters.

model.train() and model.eval() switch layers such as dropout and batch normalisation between their training and evaluation behaviour. This network has no such layers, so here the calls change nothing; they are kept because a general training loop needs them. The training loss of an epoch is computed before optimizer.step(), the validation loss after it; the two curves are shifted by one step, which is irrelevant on a scale of thousands of epochs. Finally, torch.manual_seed(0) before make_mlp gives the same initial weights as in Sections 1–2: the model trained here is exactly the one analysed above.

Code 
def train_monitored(model, n_epochs=3000, lr=1e-2):
    linear = [layer for layer in model if isinstance(layer, nn.Linear)]
    W0 = [layer.weight.detach().clone() for layer in linear]          # initial weights, for the relative change
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)
    loss_fn = nn.MSELoss()
    log = {"train": [], "val": [], "grad": [], "change": []}
    best = {"val": np.inf, "epoch": None, "state": None}
    for epoch in range(n_epochs):
        model.train()
        loss = loss_fn(model(X_train), Y_train)
        optimizer.zero_grad()
        loss.backward()
        log["grad"].append([layer.weight.grad.norm().item() for layer in linear])    # read the gradients before the step
        optimizer.step()

        model.eval()
        with torch.no_grad():
            val_loss = loss_fn(model(X_val), Y_val).item()
            log["change"].append([((layer.weight - w0).norm() / w0.norm()).item() for layer, w0 in zip(linear, W0)])
        log["train"].append(loss.item())
        log["val"].append(val_loss)
        if val_loss < best["val"]:                                     # remember the best model so far
            best = {"val": val_loss, "epoch": epoch, "state": copy.deepcopy(model.state_dict())}
    log["grad"], log["change"] = np.array(log["grad"]), np.array(log["change"])
    return log, best

7. Summary

The architecture alone already gives a layer table (shapes and parameters per layer), the total and trainable numbers of parameters (requires_grad), the memory (\(4\) bytes per float32 parameter) and the multiply-adds per sample; the number of parameters grows linearly with depth and quadratically with width. Before training, the weight and activation histograms, the fraction of saturated nodes and the gradient norms per layer show whether the initialisation scale lets signals and gradients shrink, survive or saturate with depth. During training, the training and validation losses against the epoch, together with the gradient norms and relative weight changes per layer, show how the parameters evolve. Overfitting appears as a training loss falling below the noise level while the validation loss rises; the parameters at the epoch with the smallest validation loss are kept (early stopping). The test set is used once, for the chosen model, and residual plots show whether its errors are random or systematic.

def train_early_stopping(model, max_epochs=3000, patience=200, lr=1e-2):
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)
    best_val, best_epoch, best_state = np.inf, 0, None
    train_hist, val_hist = [], []
    for epoch in range(max_epochs):
        model.train()
        loss = loss_fn(model(X_train), Y_train)
        optimizer.zero_grad(); loss.backward(); optimizer.step()
        model.eval()
        with torch.no_grad():
            val = loss_fn(model(X_val), Y_val).item()
        train_hist.append(loss.item()); val_hist.append(val)
        if val < best_val:
            best_val, best_epoch, best_state = val, epoch, copy.deepcopy(model.state_dict())
        elif epoch - best_epoch >= patience:          # no improvement for `patience` epochs
            break                                     # leave the loop; `epoch` keeps its last value
    model.load_state_dict(best_state)                 # restore the best parameters
    return epoch, best_epoch, train_hist, val_hist
