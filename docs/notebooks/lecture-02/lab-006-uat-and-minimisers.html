Lab 006 — Universal approximation and minimisers

In the lecture (and in Chapter 2 of the Lecture Notes) we wrote the simplest neural network, one hidden layer with \(N\) neurons: \[f(x;\vec\theta) = \sum_{i=1}^{N} W^{(2)}_i\,\sigma\big(W^{(1)}_i x + b_i\big), \qquad \vec\theta = \{W^{(1)}_i, b_i, W^{(2)}_i\}_{i=1}^{N},\quad \dim\vec\theta = 3N . \tag{1}\] The Universal Approximation Theorem (UAT; Cybenko 1989) states: for a continuous \(g\) on a compact (closed and bounded) set \(\mathcal X\), a continuous sigmoidal activation \(\sigma\) (the logistic sigmoid; the same holds for \(\tanh\) and, more generally, for any non-polynomial continuous activation) and any positive \(\epsilon\) there exist \(N\) and parameters \(\vec\theta\) such that \[\sup_{x\in \mathcal X}\big|f(x;\vec\theta) - g(x)\big| < \epsilon . \tag{2}\] The theorem says that good parameters exist. It does not say how to find them. Finding them is an optimisation problem: \[\vec\theta^\ast = \arg\min_{\vec\theta}\mathcal L(\vec\theta), \qquad \mathcal L(\vec\theta) = \frac1K\sum_{k=1}^{K}\big(g(x_k) - f(x_k;\vec\theta)\big)^2 , \tag{3}\] where \(x_1,\dots,x_K\) are the sampling points (Section 1). The supremum in equation (2) is the largest value of \(|f-g|\) on \(\mathcal X\); for a continuous function on a closed interval it equals the maximum, so the theorem bounds the worst-case error. The arg min in equation (3) denotes the parameter vector at which \(\mathcal L\) is smallest (not the smallest value itself). The result depends on how we minimise, and this is the thread of the notebook. After fixing the target function and the dataset, we look at what one neuron and a pair of neurons can represent, and build an approximation without any optimisation, choosing all parameters ourselves (a constructive version of the UAT). We then write the loss as a function of a parameter vector, derive its gradient analytically, and hand the problem to the minimisers of SciPy: gradient-free ones (Nelder–Mead, Powell) and gradient-based ones that use the analytic gradient (gradient descent, conjugate gradient (CG), Broyden–Fletcher–Goldfarb–Shanno (BFGS) and its limited-memory variant L-BFGS). The same problem is then solved in PyTorch, with autograd and the optimisers of torch.optim (stochastic gradient descent (SGD), momentum, RMSprop, Adam, L-BFGS). With these tools we follow the loss as a function of the number of neurons \(N\), build approximators for harder targets with a free choice of \(N\), activation and minimiser, look at the non-convex landscape in which different starts lead to different minima, and check what the network does outside the training interval. A summary and exercises close the notebook.

1. Target function and dataset

We use the example from the Lecture Notes, \[g(x) = x^2\sin(\pi x) - \frac{1}{2+\cos x}, \qquad x\in[-2, 2], \tag{4}\] and a training set \[\mathcal D = \{(x_k, g(x_k))\}_{k=1}^{K} \tag{5}\] of \(K\) points \(x_k\), 100 of them, drawn at random (uniformly) from the interval. We deliberately do not use an equally spaced grid: in real experiments and simulations the sampling points are rarely regular, and a fit should be judged on how well it reproduces \(g\) between the sampling points. Therefore all fits are plotted on a separate dense grid x_plot.

The number of points follows from the size of the networks below, which have a few tens of parameters (30 for 10 neurons), and the number of data points should be several times larger than the number of parameters, otherwise the data do not determine the fit. Any \(K\) of order 100 serves the purpose. The seed 2026 of the random generator fixes the points, so that every run of the notebook gives the same numbers; its value is arbitrary (the same holds for all other seeds in this notebook).

2. Building blocks

2.1 One neuron

A single hidden neuron contributes \(W^{(2)}\tanh(W^{(1)}x + b)\). The weight \(W^{(1)}\) sets the steepness, the ratio \(-b/W^{(1)}\) sets the position of the step, and \(W^{(2)}\) sets its height.

In the plotting code the labels are f-strings that contain LaTeX. Inside an f-string single braces {w} insert the value of a variable, so a literal brace, needed for the LaTeX superscript W^{(1)}, is written twice: f"$W^{{(1)}} = {w}$" produces the text $W^{(1)} = 0.5$.

2.2 Two neurons make a bump

The difference of two shifted steps is a localised bump: \[\tfrac12\big[\tanh(s(x - a)) - \tanh(s(x - c))\big] \approx \begin{cases} 1, & a < x < c, \\ 0, & \text{elsewhere.}\end{cases} \tag{6}\] A sum of such bumps with suitable heights can follow any continuous curve — this is the intuition behind the UAT. Each \(\tanh\) goes from \(-1\) to \(+1\), i.e. changes by 2 across its step; the difference of two steps therefore has height 2, and the factor \(\tfrac12\) normalises the bump to height 1. The values of \(s\), \(a\) and \(c\) below (8, \(-0.5\) and 1) are arbitrary illustration values.

3. A constructive approximation (no optimisation)

Divide \([-2,2]\) into \(N\) intervals with ordered nodes \(x_0, x_1, \dots, x_N\). A staircase that jumps by \(g(x_j) - g(x_{j-1})\) at the midpoint \(m_j\) of each interval is \[f_N(x) = g(x_0) + \sum_{j=1}^{N}\big[g(x_j) - g(x_{j-1})\big]\;\frac{1 + \tanh\big(s\,(x - m_j)\big)}{2}. \tag{7}\] The function \(\tfrac12\big(1+\tanh(s(x-m_j))\big)\) is a smooth step that goes from 0 far to the left of \(m_j\) to 1 far to the right of it, so each term adds the jump \(g(x_j)-g(x_{j-1})\) once \(x\) has passed \(m_j\). This is a one-hidden-layer network with \(N\) neurons (plus a constant). We choose all parameters ourselves: \[W^{(1)}_j = s, \qquad b_j = -s\, m_j, \qquad W^{(2)}_j = \tfrac12\,[g(x_j)-g(x_{j-1})] . \tag{8}\] The factor \(\tfrac12\) in \(W^{(2)}_j\) comes from \[\tfrac12(1+\tanh z) = \tfrac12 + \tfrac12\tanh z : \tag{9}\] each term is half a jump times \(\tanh\), plus half a jump as a constant. All these constants add up to the constant of the network, \[g(x_0) + \tfrac12\sum_j[g(x_j)-g(x_{j-1})] = \tfrac12[g(x_0)+g(x_N)] . \tag{10}\] As \(N\) grows without bound (with \(s\) growing so that steps stay sharp) the error goes to zero — a constructive version of the theorem.

Two details of the code concern the steepness and broadcasting. The intervals have width \(h\) and we take the steepness \(s\) as \[h = 4/N, \qquad s = 4N, \qquad s\,h = 16 : \tag{11}\] each step rises from 0 to 1 within a small fraction of its interval, and the network is a genuine staircase. The factor 4 is arbitrary. Smaller factors make neighbouring steps overlap; the sum then becomes a smoother interpolation and is in fact somewhat more accurate (with factor 1 the error for 64 neurons and more is about 2.5 times smaller), but the sharp version shows the construction better.

Indexing with None adds an axis of length 1: x[:, None] is a column of shape \((K, 1)\) and mids[None, :] a row of shape \((1, N)\). Their difference is broadcast to a \((K, N)\) table whose entry \((k, j)\) is \(x_k - m_j\), i.e. neuron \(j\) evaluated at point \(k\). The product hidden @ jumps then sums over the neurons.

Code 
def staircase(x, N, steepness_factor=4.0):
    """Explicitly constructed one-hidden-layer tanh network approximating g with N neurons."""
    nodes = np.linspace(-2, 2, N + 1)
    mids = 0.5 * (nodes[1:] + nodes[:-1])
    jumps = g(nodes[1:]) - g(nodes[:-1])
    s = steepness_factor * N                       # steps get sharper as intervals shrink
    hidden = 0.5 * (1 + np.tanh(s * (x[:, None] - mids[None, :])))   # shape (len(x), N)
    return g(nodes[0]) + hidden @ jumps

fig, axes = plt.subplots(1, 2, figsize=(13, 4))
axes[0].plot(x_fine, g(x_fine), "k", lw=2, label="$g(x)$")
for N in [5, 10, 40]:
    axes[0].plot(x_fine, staircase(x_fine, N), label=f"$N = {N}$")
axes[0].set_xlabel("$x$"); axes[0].legend()

Ns = np.array([4, 8, 16, 32, 64, 128, 256, 512])
sup_err = [np.max(np.abs(staircase(x_fine, N) - g(x_fine))) for N in Ns]
axes[1].loglog(Ns, sup_err, "o-", label=r"$\max_x |f_N(x) - g(x)|$")
axes[1].loglog(Ns, 20 / Ns, "k--", label=r"$\propto 1/N$")   # guide line; the prefactor 20 only places it near the points

The construction works but is inefficient: the error decreases only like \(1/N\), and it needs \(g\) at equally spaced nodes of our choice. The \(1/N\) law follows from the shape of a staircase: within one interval it is (nearly) constant, while \(g\) changes by up to \(|g'|_{\max}\,h\), with \(h\) from equation (11). The error is therefore at most about half of such a change, \[\tfrac12|g'|_{\max}\cdot 4/N \approx 26/N , \qquad |g'|_{\max}\approx 12.9 \ \text{on}\ [-2,2] ; \tag{12}\] the measured error is about \(18/N\) for large \(N\). In practice the sampling points are given, and a minimiser has to choose all \(3N\) parameters, including the positions of the steps. Section 7 shows that an optimised network with about 8 neurons is more accurate than the staircase with 512 neurons.

4. Loss function of the parameter vector

Most minimisers (in particular scipy.optimize.minimize) work with a flat vector \(\vec\theta\) of \(3N\) parameters. We store \[\vec\theta = (W^{(1)}_1,\dots,W^{(1)}_N,\; b_1,\dots,b_N,\; W^{(2)}_1,\dots,W^{(2)}_N) \tag{13}\] and unpack it inside the model.

In the model, np.outer(x, W1) is the \(K\times N\) matrix with entries \(x_k W^{(1)}_i\). Adding the length-\(N\) vector b adds \(b_i\) to every entry of column \(i\) (broadcasting), so entry \((k, i)\) of the table is the argument of neuron \(i\) at point \(k\). Multiplying by W2 with @ sums the neurons with their output weights.

The random initial parameters are not arbitrary in their order of magnitude. We draw \[W^{(1)}_i,\ b_i \sim \mathcal N(0, 2^2), \qquad W^{(2)}_i \sim \mathcal N(0, 1/N) . \tag{14}\] On \([-2,2]\) a neuron \(\tanh(W^{(1)}x+b)\) is a step at the position \(-b/W^{(1)}\) of width about \(1/|W^{(1)}|\). Values of order 2 give steps that are narrower than the interval and positions \(-b/W^{(1)}\) that are of order 1, i.e. mostly inside the interval. Much smaller values give nearly linear neurons, much larger values give very sharp steps with vanishing slope almost everywhere. The output weights are drawn with variance \(1/N\). The output is a sum of \(N\) terms of random sign, so its variance is \(N\cdot\mathrm{Var}(W^{(2)})\) times a number of order 1. With the variance \(1/N\) of equation (14) the initial \(f(x)\) is of order 1, comparable to \(g\), for every \(N\) (the standard deviation of \(W^{(2)}\) scales as \(1/\sqrt N\)).

Ten neurons (30 parameters) are small enough for the gradient-free methods and the finite-difference gradients below to finish in seconds, and large enough for a good fit.

Code 
def unpack(theta):
    """Split the flat parameter vector into (W1, b, W2), each of length N."""
    N = theta.size // 3                         # // is integer division: 30 // 3 = 10 (an integer, usable as an index)
    return theta[:N], theta[N:2 * N], theta[2 * N:]

def model(theta, x):
    """f(x; theta) = sum_i W2_i tanh(W1_i x + b_i), evaluated for all x at once."""
    W1, b, W2 = unpack(theta)
    hidden = np.tanh(np.outer(x, W1) + b)       # shape (K, N): neuron i evaluated at point k
    return hidden @ W2                          # shape (K,)

def loss(theta, x=x_train, y=y_train):
    """Mean squared error on the training set."""
    return np.mean((model(theta, x) - y)**2)

def init_theta(N, seed):
    """Random initial parameters: input weights and biases ~ N(0, 2^2), output weights ~ N(0, 1/N)."""
    rng = np.random.default_rng(seed)
    # np.concatenate joins the three length-N arrays into one flat vector of length 3N
    return np.concatenate([rng.normal(0, 2, N), rng.normal(0, 2, N), rng.normal(0, 1, N) / np.sqrt(N)])

N = 10
theta0 = init_theta(N, seed=0)        # ONE common starting point for all minimisers below
print("number of parameters:", theta0.size, "  initial loss:", loss(theta0))
number of parameters: 30   initial loss: 1.0398383815103345

The network whose 30 parameters are chosen by the minimisers has one input \(x\), one hidden layer of 10 neurons with \(\tanh\), and one output \(f(x)\) that sums the hidden neurons with the weights \(W^{(2)}_i\) (this network has no output bias). Each line from the input to hidden neuron \(i\) carries the weight \(W^{(1)}_i\), and the neuron adds its bias \(b_i\); each line from neuron \(i\) to the output carries \(W^{(2)}_i\).

draw_network is the drawing function used for network diagrams throughout the course. It draws a dense network as columns of circles, one column per layer and one circle per neuron, and joins every circle with every circle of the next column by a thin grey line, one line per weight. The height of a column grows with the logarithm of the layer size, so that a wide layer looks taller than a narrow one and a network that compresses its input visibly narrows. A layer with more neurons than max_nodes is drawn with its first and last few neurons and a vertical ellipsis in between; its true size is always written under the column. The colours follow one convention in all notebooks: grey for the data at the input and at the output, blue for hidden layers, orange for a latent (bottleneck) layer and green for an additional input such as a class label.

To draw your own network, pass the list of layer sizes from the input to the output, for example draw_network([784, 128, 64, 10]), and, if you wish, a list of names (labels) and of colours (colors) with one entry per column. An entry of layer_sizes can itself be a list, such as [16, 16], which stacks two blocks in one column; groups draws a bracket with a name above a range of columns, and no_input lists blocks that receive no edges from the previous column. The function returns the matplotlib axes, so the figure can be changed further or saved with ax.figure.savefig(...). It needs only NumPy and matplotlib and therefore also runs in Colab. The comments in the code explain each step (node positions, the truncation of large layers, the edges, the labels and the brackets), so that the function can be adapted to other diagrams.

Code 
import numpy as np
import matplotlib.pyplot as plt
from matplotlib.patches import Circle

# Colours used for the network drawings: grey for the data (input and output),
# blue for hidden layers, orange for the latent (bottleneck) layer and green
# for an extra conditioning input such as a one-hot class label.
GREY, BLUE, ORANGE, GREEN = "#8C8C8C", "#005CA7", "#EB6709", "#2E8B57"


def draw_network(layer_sizes, labels=None, colors=None, max_nodes=10,
                 groups=None, no_input=None, ax=None, node_radius=0.11,
                 x_gap=1.6, min_height=1.0, height_scale=1.1, fontsize=13):
    """Draw a fully connected network as columns of circles joined by edges.

    Parameters
    ----------
    layer_sizes : list
        One entry per column, from the input to the output. An entry is
        either an int (the number of neurons of one layer) or a list of ints
        (several blocks stacked in the same column, e.g. [16, 16] for the mean
        and the log-variance of a variational autoencoder, or [784, 10] for an
        image together with a one-hot condition).
    labels : list, optional
        Names shown under each column next to the true layer size. An entry
        may be None (size only), a string, or, for a stacked column, a list
        with one string per block.
    colors : list, optional
        Fill colour of the nodes of each column (or a list with one colour per
        block). By default the first and the last column are grey and all
        others blue.
    max_nodes : int
        Largest number of circles drawn for one block. A larger block is shown
        by its first and last few nodes with a vertical ellipsis in between;
        the true size is always shown in the label.
    groups : list of (text, first_column, last_column), optional
        Brackets drawn above a range of columns, e.g. ("encoder", 0, 2).
    no_input : list of (column, block), optional
        Blocks that receive no edges from the previous column, e.g. a condition
        c that enters the decoder from outside.
    ax : matplotlib Axes, optional
        Axes to draw into; a new figure is created when None.
    node_radius, x_gap : float
        Radius of a circle and horizontal distance between columns.
    min_height, height_scale : float
        The height of a block of size s is min_height + height_scale*log10(s),
        so that a narrow layer is visibly shorter than a wide one.
    fontsize : int
        Font size of all labels.

    Returns
    -------
    ax : the matplotlib Axes with the drawing.
    """
    n = len(layer_sizes)
    # Turn every entry into a list of blocks, so that a plain layer is a
    # column with a single block.
    blocks = [s if isinstance(s, (list, tuple)) else [s] for s in layer_sizes]
    if labels is None:
        labels = [None] * n
    if colors is None:
        colors = [GREY] + [BLUE] * (n - 2) + [GREY]
    no_input = set(no_input or [])

    def per_block(value, k):
        # Repeat a single value for all k blocks of a column, or keep a list.
        return list(value) if isinstance(value, (list, tuple)) else [value] * k

    if ax is None:
        _, ax = plt.subplots(figsize=(1.9 * n + 1, 5.5))

    # ---- Node positions ---------------------------------------------------
    # Column i sits at x = i * x_gap. Inside a column the blocks are stacked
    # from top to bottom with a small gap, and the whole column is centred
    # on y = 0. Each block gets a height that grows with log10 of its size
    # (but is never too small for its circles to fit without overlapping);
    # the drawn nodes are spread evenly over that height.
    nodes = []            # nodes[i][b] = list of (x, y) of block b in column i
    tops, bottoms = [], []
    gap = 0.9             # vertical space between stacked blocks (holds a label)
    for i, blk in enumerate(blocks):
        cols = per_block(colors[i], len(blk))
        labs = per_block(labels[i], len(blk))
        heights = [max(min_height + height_scale * np.log10(s),
                       (min(s, max_nodes) - 1) * 2.3 * node_radius) for s in blk]
        total = sum(heights) + gap * (len(blk) - 1)
        x, y_top = i * x_gap, total / 2
        column = []
        for s, h, c, lab in zip(blk, heights, cols, labs):
            shown = min(s, max_nodes)
            if s <= max_nodes:
                # Small block: draw every neuron.
                ys = np.linspace(y_top, y_top - h, shown) if shown > 1 else np.array([y_top - h / 2])
            else:
                # ---- Truncation of large layers ----------------------------
                # Draw max_nodes circles: half in the upper 38 % of the block,
                # half in the lower 38 %, and a vertical ellipsis in the
                # middle to show that neurons are omitted.
                k = max_nodes // 2
                ys = np.concatenate([np.linspace(y_top, y_top - 0.38 * h, k),
                                     np.linspace(y_top - 0.62 * h, y_top - h, max_nodes - k)])
                ax.text(x, y_top - 0.5 * h, r"$\vdots$", ha="center", va="center",
                        fontsize=fontsize + 6, color=c, zorder=4)
            for y in ys:
                ax.add_patch(Circle((x, y), node_radius, facecolor=c,
                                    edgecolor="black", lw=0.6, zorder=3))
            column.append([(x, y) for y in ys])

            # ---- Labels of stacked blocks ----------------------------------
            # In a column with several blocks each block is labelled just

4.1 Gradient of the loss

The gradient follows from backpropagation through the single hidden layer. With \[a_{ki} = W^{(1)}_i x_k + b_i, \qquad h_{ki} = \tanh a_{ki}, \qquad f_k = \sum_i W^{(2)}_i h_{ki}, \qquad r_k = f_k - y_k , \tag{15}\] where \(r_k\) are the residuals, \[\frac{\partial\mathcal L}{\partial W^{(2)}_i} = \frac{2}{K}\sum_k r_k\,h_{ki},\qquad \frac{\partial\mathcal L}{\partial b_i} = \frac{2}{K}\sum_k r_k\,W^{(2)}_i\,(1 - h_{ki}^2),\qquad \frac{\partial\mathcal L}{\partial W^{(1)}_i} = \frac{2}{K}\sum_k r_k\,W^{(2)}_i\,(1 - h_{ki}^2)\,x_k . \tag{16}\] The factors come from the chain rule, \[\frac{\partial\mathcal L}{\partial f_k} = \frac{2r_k}{K}, \quad \frac{\partial f_k}{\partial W^{(2)}_i} = h_{ki}, \quad \frac{\partial f_k}{\partial h_{ki}} = W^{(2)}_i, \quad \frac{\partial h_{ki}}{\partial a_{ki}} = 1-h_{ki}^2, \quad \frac{\partial a_{ki}}{\partial b_i} = 1, \quad \frac{\partial a_{ki}}{\partial W^{(1)}_i} = x_k . \tag{17}\] Each parameter affects \(\mathcal L\) through all \(K\) points, hence the sums over \(k\). (The derivative of \(\tanh\) is \(1 - \tanh^2\).) This is the chain rule applied backwards through the network; autograd performs the same computation automatically.

An analytically derived gradient is easy to get wrong, so we compare it with the central difference \[\frac{\mathcal L(\vec\theta+\delta\vec e) - \mathcal L(\vec\theta-\delta\vec e)}{2\delta} \tag{18}\] for every unit vector \(\vec e\), with step \(\delta\) (eps in the code). Its truncation error is of order \(\delta^2\) and its round-off error of order \(10^{-16}/\delta\), so \(\delta\) between about \(10^{-4}\) and \(10^{-7}\) gives differences of \(10^{-9}\) or smaller; we take \(\delta\) of \(10^{-6}\). The gradient components here are of order 1, so a mistake in one of the formulas would show up as a difference of order 1, not \(10^{-10}\). The largest difference printed below is \(2.2\times10^{-10}\): the formulas are correct.

Code 
def grad(theta, x=x_train, y=y_train):
    """Analytic gradient of the MSE loss with respect to theta = (W1, b, W2)."""
    W1, b, W2 = unpack(theta)
    K = x.size
    h = np.tanh(np.outer(x, W1) + b)            # (K, N) hidden activations
    r = h @ W2 - y                              # (K,)   residuals
    dW2 = 2 / K * h.T @ r                       # (N,)   (2/K) sum_k r_k h_ki
    delta = 2 / K * r[:, None] * W2[None, :] * (1 - h**2)   # (K, N) dL/da_ki
    db = delta.sum(axis=0)                      # (N,)   sum over the points k
    dW1 = delta.T @ x                           # (N,)   sum_k delta_ki x_k
    return np.concatenate([dW1, db, dW2])

5. Minimisers in SciPy

scipy.optimize.minimize(fun, x0, method=..., jac=...) gives access to many classical algorithms. We compare two families:

method uses idea
Nelder–Mead only \(\mathcal L\) moves a simplex of \(3N+1\) points by reflections/contractions
Powell only \(\mathcal L\) successive 1D line minimisations along a set of directions
CG (conjugate gradient) \(\mathcal L\), \(\nabla\mathcal L\) line searches along conjugate-gradient directions: each new direction is the gradient corrected so that it does not undo the progress along the previous directions
BFGS (Broyden–Fletcher–Goldfarb–Shanno) \(\mathcal L\), \(\nabla\mathcal L\) quasi-Newton: builds an approximation of the inverse Hessian from gradient history
L-BFGS-B \(\mathcal L\), \(\nabla\mathcal L\) BFGS with limited memory (stores the last few differences of parameters and gradients) — usable for many parameters; “-B”: optional bounds on the parameters, not used here

Two terms used in the table: a simplex in \(n\) dimensions is a set of \(n+1\) points (a triangle in two dimensions, a tetrahedron in three); Nelder–Mead compares \(\mathcal L\) at its corners and moves the worst corner. A line search (line minimisation) is a one-dimensional minimisation of \(\mathcal L(\vec\theta + \alpha\vec d)\) over the step length \(\alpha\) along a chosen direction \(\vec d\).

To follow the progress we pass a callback, which SciPy calls after every iteration with the current \(\vec\theta\). We also count how many times \(\mathcal L\) was evaluated (nfev) and, for the methods that use it, how many times the gradient was evaluated (njev); with the analytic gradient one gradient costs about as much as a few evaluations of \(\mathcal L\). message reports why the minimiser stopped.

The function minimize returns an OptimizeResult object: res.x is the parameter vector at the end of the run, res.fun the loss there, and res.nfev/res.njev the numbers of loss and gradient evaluations. Results of the gradient-free methods have no attribute njev; since getattr(obj, "name", default) returns the attribute if it exists and default otherwise, the code works for all methods. The default iteration limits differ between methods, so we set a common maxiter = 5000. With it every method can stop on its own convergence criterion, except Nelder–Mead, which reaches the limit (with 20000 iterations it gets to \(5\cdot10^{-2}\), still far from the other methods, at four times the cost). Each method has its own default stopping tolerance, so the final losses are not compared at equal accuracy; they show what each method delivers with its standard settings.

5.1 Plain gradient descent

Plain gradient descent uses the analytic gradient in the update \[\vec\theta_{t+1} = \vec\theta_t - \eta\,\nabla\mathcal L(\vec\theta_t) \tag{19}\] with fixed learning rate \(\eta\).

The size of \(\eta\) is limited. Near a minimum \(\mathcal L\) is approximately quadratic, and along the eigenvector of the Hessian with the largest eigenvalue \(\lambda_{\max}\) one step multiplies the distance to the minimum by \((1-\eta\lambda_{\max})\). The iteration is stable only if \[|1-\eta\lambda_{\max}|<1, \qquad\text{i.e.}\qquad \eta < 2/\lambda_{\max} ; \tag{20}\] otherwise the parameters oscillate with growing amplitude. For our start \(\lambda_{\max}\) is about 9, so the limit of equation (20) is a learning rate of about 0.2. We measured: the learning rate 0.5 diverges within 10 steps, while learning rates up to \(0.3\) do not diverge in 20000 steps: the parameters drift into a region where the landscape is flatter (at the end of the run with 0.3, \(\lambda_{\max}\) is about 6.7, close to \(2/0.3\)), so the estimate from the starting point is only a rough guide. The learning rate 0.05 is a safe choice well below the limit, not an optimal one (0.1 reaches a loss about 3 times lower here); Exercise 3 scans \(\eta\) systematically. Because each step is small, the loss decreases slowly along the flat directions of the landscape, hence the large number of steps.

6. Autograd and torch.optim

Here autograd computes the gradient, and we compare the optimisers used in deep learning (see The Zoo of Optimization Algorithms in the Lecture Notes). We start from the same \(\vec\theta_0\). L-BFGS in PyTorch needs a closure — a function that recomputes the loss and gradient, because it evaluates them several times per step (line search).

In the code, getattr(torch.optim, "Adam") is the same object as torch.optim.Adam: the optimiser class is selected from its name given as a string, so one function run_torch serves all optimisers. In the definition of a function, **opt_kwargs collects all extra keyword arguments into a dictionary; in a call, **kw unpacks a dictionary into keyword arguments, so run_torch("SGD", 2000, **dict(lr=0.05)) is the same as run_torch("SGD", 2000, lr=0.05). The call opt.step(closure) returns the loss computed by the (first) call of the closure, i.e. the loss before the update of this step, and .item() turns the one-element tensor into a Python number, so the list history does not keep the computational graph in memory.

The learning rates differ between the optimisers. With momentum \(\beta\) of 0.9 the steps accumulate along a steady slope to about \[\frac{\mathrm{lr}}{1-\beta} = 10\,\mathrm{lr} , \tag{21}\] so momentum needs a smaller lr than plain SGD. RMSprop and Adam divide the gradient by a running average of its size, so for them lr is roughly the step length in parameter units, independent of the size of the gradient. All these values were tuned to give stable runs; they are typical, not optimal (Exercise 3 scans the learning rate).

For L-BFGS, max_iter = 20 is the number of inner quasi-Newton iterations per call of step, so 50 outer steps allow up to 1000 iterations (each with several evaluations of the loss in the line search), comparable in cost to the 2000 steps of the first-order methods. The numbers of steps are kept small so that the cell runs in a few seconds; with 5000 steps the first-order methods reach lower losses (we measured Adam \(9\cdot10^{-5}\), momentum \(4\cdot10^{-3}\), RMSprop \(10^{-2}\), SGD \(6\cdot10^{-2}\)). lr = 1 is the natural step length, because a quasi-Newton direction already has the scale of a Newton step. Without a line search PyTorch takes this fixed step, which can increase the loss; with line_search_fn="strong_wolfe" the step length is adjusted at every iteration so that the loss decreases sufficiently (the Wolfe conditions).

Code 
xt, yt = torch.tensor(x_train), torch.tensor(y_train)

def model_torch(theta, x):
    """Same network as `model`, written with torch operations."""
    N = theta.numel() // 3
    W1, b, W2 = theta[:N], theta[N:2 * N], theta[2 * N:]
    return torch.tanh(x[:, None] * W1 + b) @ W2

def run_torch(opt_name, n_steps, **opt_kwargs):
    theta = torch.tensor(theta0, requires_grad=True)          # fresh copy of the common start
    opt = getattr(torch.optim, opt_name)([theta], **opt_kwargs)
    history = []

    def closure():                                            # forward + backward; used by every optimiser
        opt.zero_grad()
        L = torch.mean((model_torch(theta, xt) - yt)**2)
        L.backward()
        return L

    t0 = time.perf_counter()
    for _ in range(n_steps):
        L = opt.step(closure)                                 # SGD/Adam call closure once, LBFGS several times
        history.append(L.item())
    return dict(theta=theta.detach().numpy(), history=history, final_loss=history[-1],
                time=time.perf_counter() - t0)

Gradient-free methods (Nelder–Mead, Powell) need many function evaluations already for 30 parameters, and Nelder–Mead stopped at the iteration limit without converging (see its message above). Methods that use curvature information (BFGS, L-BFGS), which build an approximation of the curvature (the Hessian) from the history of gradients, or conjugate directions (CG) are the most accurate for this small, smooth, full-batch problem. First-order methods (SGD, momentum, RMSprop, Adam) are slower to converge here, but they are the only ones that remain practical for millions of parameters and mini-batches of data (at every step the gradient is computed from a random subset of the data, which makes it noisy), which is the situation in deep learning. Every method has hyperparameters (learning rate, momentum, number of steps), and with other values the ranking can change (Exercise 3).

7. Loss and the number of neurons

The UAT promises that the error can be made small by increasing \(N\), a claim that can be tested numerically. For each \(N\) we run BFGS from a few random starting points and keep the best result. The restarts are needed because the landscape is non-convex (Section 9), so a single run can end in a poor minimum. Three starts per \(N\) (seeds 0, 1, 2) are a compromise between cost and the chance of missing a good minimum; any small number (3–10) is reasonable.

BFGS stops when the largest component of the gradient falls below gtol (default \(10^{-5}\)), or after maxiter iterations. With the default gtol, the run for 8 neurons stops at a loss of about \(10^{-6}\), although much lower losses exist: near such a small minimum the gradient is already tiny. We therefore set gtol = 1e-8. To keep the cell fast we allow at most 1000 iterations, and for 6 neurons and more the runs stop at this limit. Their losses (of order \(10^{-7}\)) are therefore set by the iteration budget, not by \(N\). With max_iter = 5000 (about four times longer) we measured \(1.6\cdot10^{-9}\) for 8 neurons and \(10^{-10}\) for 12.

8. Approximators for other functions

One tool collects everything and builds the approximator \[f(x;\vec W^{(1)},\vec b,\vec W^{(2)}) = \sum_{i=1}^{N} W^{(2)}_i\,\sigma\big(W^{(1)}_i x + b_i\big) + c \tag{22}\] for any target \(g(x)\) on an interval \([x_\min, x_\max]\), with a chosen number of hidden nodes \(N\) (we use ‘node’ and ‘neuron’ interchangeably), activation \(\sigma\), number of sampling points \(K\) and minimiser. We add an output bias \(c\): for activations that are not odd functions (sigmoid, ReLU, …), it is needed to shift the output; for \(\tanh\) it changes little.

The function fit_uat follows the recipe of the lecture. It samples \(K\) points \(x_k\) in the interval and computes the data \(y_k\) as \(g(x_k)\); it sets up the model with the parameters \(\vec W^{(1)}, \vec b, \vec W^{(2)}\) and \(c\), initialised randomly; it defines the loss \[\mathcal L(\vec\theta) = \frac1K\sum_k \big(y_k - f(x_k;\vec\theta)\big)^2 ; \tag{23}\] and it minimises the loss by repeatedly computing \(\mathcal L\), computing \(\nabla_{\vec\theta}\mathcal L\) by autograd and updating \(\vec\theta\). Since the landscape is non-convex, the whole procedure can optionally be repeated from a few random starts (n_restarts), keeping the best result.

Several choices inside fit_uat need a justification. The input \(x\) is rescaled, i.e. mapped linearly to \([-1, 1]\) before entering the network. The random initial steps have positions \(-b_i/W^{(1)}_i\) of order 1 and widths \(1/|W^{(1)}_i|\) of order \(1/3\), so they cover \([-1,1]\) well. On an interval far from this scale the same initialisation fails: for \(g\) shifted to \([100, 104]\) (8 nodes) the loss stays at 1.4, which is the variance of the data (no fit at all, every \(\tanh\) is saturated), while with rescaling it reaches \(3\cdot10^{-6}\); on \([-0.02, 0.02]\) the numbers are 0.13 and \(2\cdot10^{-5}\). For the intervals of the gallery, all of width 2–6 around 0, rescaling makes little difference, but it costs nothing. The output \(y\) is not rescaled; the targets below are of order 1.

The initial weights are drawn as in equation (14), but with standard deviation 3 instead of 2 for \(W^{(1)}_i\) and \(b_i\). The value 3 is arbitrary. We tested standard deviations 1, 3, 5 and 10 with 8 nodes: for the smooth targets all of them give small final losses, with no systematic trend; for the sawtooth the final loss ranges from \(10^{-4}\) to \(10^{-1}\) and depends mainly on which minimum the run happens to reach (Section 9), not on this value.

The output bias \(c\) starts at the mean of the data, so the nodes only have to represent the deviations from the mean. Starting from zero also works. The default numbers of steps and the learning rates follow Section 6: L-BFGS needs some tens of outer steps with lr 1, first-order methods need thousands of steps with a small lr. The defaults (30 L-BFGS steps of up to 20 inner iterations each, 2000 Adam/SGD steps, a single start) are kept small so that every figure below takes only a few seconds; larger values (e.g. n_steps=100, n_restarts=5) give lower losses for the larger \(N\), at a correspondingly higher cost.

Code 
import torch.nn.functional as F    # PyTorch module with activation functions written as plain functions, e.g. F.elu(z)

# Activation functions from the lecture slide
ACTIVATIONS = {
    "sigmoid":   torch.sigmoid,
    "tanh":      torch.tanh,
    "ReLU":      torch.relu,
    "LeakyReLU": lambda z: F.leaky_relu(z, negative_slope=0.1),
    "ELU":       F.elu,
}

def fit_uat(g, x_range, N, K=30, activation="tanh", optimizer="LBFGS",
            n_steps=None, lr=None, n_restarts=1, sampling="random", seed=0):
    """
    Fit f(x) = sum_i W2_i * sigma(W1_i * x + b_i) + c  to the function g on the interval x_range.

    g          : function of a NumPy array (the target)
    x_range    : (x_min, x_max)
    N          : number of nodes in the single hidden layer
    K          : number of sampling (training) points
    activation : key of ACTIVATIONS
    optimizer  : "LBFGS", "Adam" or "SGD"
    n_restarts : number of random initialisations; the best one is returned
    sampling   : "random" (uniformly random points) or "grid" (equally spaced points)
    Returns a dict with the fitted predictor, the data, the final loss and the loss history.
    """
    sigma = ACTIVATIONS[activation]
    x_min, x_max = x_range
    rng = np.random.default_rng(seed)

    # ---- 1. data -------------------------------------------------------------------------
    if sampling == "random":
        x_data = np.sort(rng.uniform(x_min, x_max, K))
    else:
        x_data = np.linspace(x_min, x_max, K)
    y_data = g(x_data)
    to_unit = lambda x: 2 * (x - x_min) / (x_max - x_min) - 1      # rescale input to [-1, 1]
    xt, yt = torch.tensor(to_unit(x_data)), torch.tensor(y_data)

    # default number of steps and learning rate for each optimiser
    defaults = {"LBFGS": (30, 1.0), "Adam": (2000, 1e-2), "SGD": (2000, 1e-2)}
    # `a or b` gives b when a is None (or 0): the default is used only when no value was passed
    n_steps = n_steps or defaults[optimizer][0]
    lr = lr or defaults[optimizer][1]

    best = None
    for restart in range(n_restarts):
        torch.manual_seed(seed + restart)
        # ---- 2. model parameters (random initialisation) -----------------------------
        W1 = (3 * torch.randn(N)).requires_grad_()               # steepness of each node
        b = (3 * torch.randn(N)).requires_grad_()                # position of each node
        W2 = (torch.randn(N) / np.sqrt(N)).requires_grad_()      # height of each node
        c = torch.tensor([float(y_data.mean())], requires_grad=True)  # output bias
        params = [W1, b, W2, c]

        def f(x):                                                # the approximator f(x; theta)
            return sigma(x[:, None] * W1 + b) @ W2 + c

        # ---- 3. loss -----------------------------------------------------------------
        # closure uses opt, which is created only further down: Python looks up the name opt when closure is CALLED
        # (inside opt.step), not when it is defined, and by then opt exists.
        def closure():
            opt.zero_grad()
            L = torch.mean((yt - f(xt))**2)
            L.backward()                                         # gradient by autograd
            return L

        # ---- 4. minimisation ---------------------------------------------------------
        if optimizer == "LBFGS":
            opt = torch.optim.LBFGS(params, lr=lr, max_iter=20, line_search_fn="strong_wolfe")
        else:
            opt = getattr(torch.optim, optimizer)(params, lr=lr)
        history = []
        for step in range(n_steps):
            L = opt.step(closure)
            history.append(L.item())
            if not np.isfinite(history[-1]):                     # stop a diverging run
                break

        # ---- 5. keep the best restart ------------------------------------------------
        # keep this restart if it is the first one, if the best so far diverged (nan), or if it is better
        if best is None or not np.isfinite(best["loss"]) or history[-1] < best["loss"]:
            # detach().clone(): an independent copy outside the autograd graph, not changed by later restarts.
            # The default argument frozen=frozen is evaluated when predict is defined, so predict keeps the
            # parameters of THIS restart (a direct reference to W1, b, ... would see the names of the last restart).
            frozen = [p.detach().clone() for p in params]
            def predict(x, frozen=frozen):
                W1_, b_, W2_, c_ = frozen
                return (sigma(torch.tensor(to_unit(np.asarray(x)))[:, None] * W1_ + b_) @ W2_ + c_).numpy()
            best = dict(predict=predict, loss=history[-1], history=history,
                        x_data=x_data, y_data=y_data, N=N, activation=activation)
    return best

8.1 A gallery of harder targets

Some functions are harder than others. The number of nodes needed depends on how many “features” (bumps, kinks, steps) the function has on the interval, and how sharp they are. Examples: - a Gaussian wave packet \(e^{-x^2}\cos(8x)\): many oscillations; - \(|x|\): a kink (not differentiable at 0); - a smoothed step \(\tanh(30x)\): very steep; - a sawtooth: several jumps; - the Lennard-Jones potential \(4(r^{-12} - r^{-6})\): steep wall plus shallow minimum (in its panel the horizontal axis is the distance \(r\)); - the ground state of the double well \[V(x) = \tfrac12x^2 + \kappa e^{-x^2/2}, \qquad \kappa = 6, \qquad \hbar = m = 1 . \tag{24}\] It is computed by discretising \[H = -\frac12\, \frac{d^2}{dx^2} + V \tag{25}\] with the three-point stencil on 400 equally spaced points in \([-6, 6]\) and diagonalising the resulting matrix.

Code 
def double_well_ground_state(x, kappa=6.0):
    """Ground-state wavefunction of V = x^2/2 + kappa exp(-x^2/2), interpolated onto x."""
    grid = np.linspace(-6, 6, 400); dx = grid[1] - grid[0]
    H = (-0.5 / dx**2 * (np.diag(np.ones(399), 1) - 2 * np.eye(400) + np.diag(np.ones(399), -1))
         + np.diag(0.5 * grid**2 + kappa * np.exp(-grid**2 / 2)))
    psi0 = np.linalg.eigh(H)[1][:, 0]
    # eigh normalises sum(psi0**2) = 1; dividing by sqrt(dx) gives sum(psi0**2) * dx = 1, the discrete form of
    # the integral normalisation. abs() removes the arbitrary overall sign (the ground state has no nodes).
    psi0 = np.abs(psi0) / np.sqrt(dx)
    return np.interp(x, grid, psi0)          # linear interpolation of the grid values psi0 at the points x

11. Summary

A network with one hidden layer is a weighted sum of shifted, stretched \(\tanh\) steps; pairs of steps make bumps, and sums of bumps approximate any continuous function. The UAT guarantees that good parameters exist, but finding them is a non-convex minimisation of \(\mathcal L(\vec\theta)\). Gradient-free methods need no derivatives but scale badly, and finite-difference gradients cost \(\mathcal O(\dim\vec\theta)\) evaluations (a number proportional to the number of parameters), while backpropagation (autograd) gives the exact gradient at the cost of a few evaluations of \(\mathcal L\), independently of \(\dim\vec\theta\). For small smooth problems quasi-Newton methods (BFGS, L-BFGS) are very effective; for large networks and mini-batches, first-order methods (SGD, Adam) are used. Different initialisations lead to different minima, and a fitted network interpolates; it does not extrapolate.

activations = {name: ACTIVATIONS[name] for name in ["tanh", "sigmoid", "ReLU"]}   # from Section 8

def fit_adam(N, act, n_steps=1000, lr=1e-2, seed=0):
    """Fit f(x) = sum_i W2_i act(W1_i x + b_i) + c with Adam; return the final loss and the parameters."""
    torch.manual_seed(seed)
    # the initialisation of Section 4 (input x in [-2, 2], not rescaled as in fit_uat)
    W1 = (2 * torch.randn(N)).requires_grad_()
    b = (2 * torch.randn(N)).requires_grad_()
    W2 = (torch.randn(N) / N**0.5).requires_grad_()
    c = torch.zeros(1, requires_grad=True)          # output bias: sigmoid and ReLU are not odd, a shift helps
    opt = torch.optim.Adam([W1, b, W2, c], lr=lr)
    for _ in range(n_steps):
        opt.zero_grad()
        pred = act(xt[:, None] * W1 + b) @ W2 + c
        L = torch.mean((pred - yt)**2)
        L.backward()
        opt.step()
    return L.item(), (W1, b, W2, c)

Exercise 3 — Learning-rate scan

For 10 neurons and the common start \(\vec\theta_0\), run SGD and Adam for 1000 steps with learning rates \(\eta\) from \(10^{-4}\) to 1 in factors of ten (use np.logspace(-4, 0, 5); a finer scan with np.logspace(-4, 0, 9) and 2000 steps takes about 3.5 times longer) and plot the final loss vs. \(\eta\) (log-log). Mark runs that diverged (nan or inf). Which optimiser is less sensitive to the choice of \(\eta\)?

Solution

Code 
lrs = np.logspace(-4, 0, 5)          # 5 values and 1000 steps keep the cell fast; 9 values and 2000 steps give a finer picture
fig, ax = plt.subplots(figsize=(7, 4.5))
for i, opt_name in enumerate(["SGD", "Adam"]):
    finals = np.array([run_torch(opt_name, 1000, lr=lr)["final_loss"] for lr in lrs])
    ok = np.isfinite(finals) & (finals < 1e3)           # diverged: nan/inf, or far above the initial loss of about 1
    # ~ok is the element-wise NOT of the boolean array: True for the diverged runs; np.full(n, 1e1) is an array of n values 10
    ax.loglog(lrs[ok], finals[ok], "o-", color=f"C{i}", label=opt_name)
    ax.loglog(lrs[~ok], np.full((~ok).sum(), 1e1), "x", color=f"C{i}", ms=12)   # crosses at an arbitrary height 10
ax.set_xlabel(r"learning rate $\eta$"); ax.set_ylabel("final loss (x = diverged)")
ax.legend(); plt.show()
# SGD converges slowly for small eta and diverges once eta exceeds a threshold (the crosses).
# Adam divides each step by the square root of a running average of the squared gradient, so its step length is
# about eta independently of the size of the gradient; it does not diverge in the scanned range and reaches much
# lower losses, with an optimum at an intermediate eta.

Exercise 4 — Neural surrogate for a quantum calculation

The ground-state energy \(E_0(\kappa)\) of the double well of equation (24), with \(\kappa\) now a free parameter, can be computed by exact diagonalisation of the finite-difference Hamiltonian. Suppose each diagonalisation were expensive and we could afford only 12 of them. 1. Compute \(E_0(\kappa_j)\) for 12 randomly chosen values \(\kappa_j\) in \([0, 12]\) (the first lines of the solution build the data; you may copy them). 2. Fit a one-hidden-layer network (8 neurons, \(\tanh\), with output bias) to these 12 points, in PyTorch with L-BFGS. Rescale the input to \([-1,1]\) first. 3. Compare the network with the exact \(E_0(\kappa)\) on a fine grid of 100 points. 4. Use autograd on the network to get \(dE_0/d\kappa\) and compare with the exact derivative (Hellmann–Feynman). Is the derivative of a good fit also a good approximation of the derivative?

Solution

Code 
xg = np.linspace(-6, 6, 300); dxg = xg[1] - xg[0]
H_kin = -0.5 / dxg**2 * (np.diag(np.ones(299), 1) - 2 * np.eye(300) + np.diag(np.ones(299), -1))
def E0_and_dE0(kappa):
    """Exact ground-state energy and its derivative (Hellmann-Feynman) for barrier height kappa."""
    E, psi = np.linalg.eigh(H_kin + np.diag(0.5 * xg**2 + kappa * np.exp(-xg**2 / 2)))
    # Hellmann-Feynman: dE0/dkappa = <psi0| dH/dkappa |psi0> with dH/dkappa = exp(-x^2/2).
    # eigh normalises sum(psi**2) = 1, so the expectation value is a plain sum (no factor dx).
    return E[0], np.sum(psi[:, 0]**2 * np.exp(-xg**2 / 2))

# 1) the 12 "expensive" data points and a fine reference grid
k_train = np.sort(np.random.default_rng(3).uniform(0, 12, 12))     # 12 random, non-equidistant points
E_train = np.array([E0_and_dE0(k)[0] for k in k_train])
k_fine = np.linspace(0, 12, 100)
# the list of 100 pairs (E0, dE0) becomes an array of shape (100, 2); .T gives shape (2, 100), whose two rows are unpacked
E_fine, dE_fine = np.array([E0_and_dE0(k) for k in k_fine]).T

# 2) network with output bias; input rescaled from [0, 12] to [-1, 1]
to_unit = lambda k: (k - 6.0) / 6.0
torch.manual_seed(0)
N = 8
# standard deviation 1 (an arbitrary choice): on the rescaled input [-1, 1] it already places the steps inside the interval
W1, b, W2 = torch.randn(N, requires_grad=True), torch.randn(N, requires_grad=True), torch.randn(N, requires_grad=True)
c = torch.tensor([E_train.mean()], requires_grad=True)
net = lambda k: torch.tanh(to_unit(k)[:, None] * W1 + b) @ W2 + c

kt, Et = torch.tensor(k_train), torch.tensor(E_train)
opt = torch.optim.LBFGS([W1, b, W2, c], lr=1, max_iter=50, line_search_fn="strong_wolfe")
def closure():
    opt.zero_grad()
    L = torch.mean((net(kt) - Et)**2)
    L.backward()
    return L
for _ in range(10):          # with 25 parameters and 12 points the loss stops changing after 5 outer steps
    L = opt.step(closure)
print(f"training loss: {L.item():.2e}")

# 3) and 4) prediction and its derivative on the fine grid (autograd w.r.t. the INPUT kappa)
kf = torch.tensor(k_fine, requires_grad=True)
E_pred = net(kf)
# E_pred[j] depends only on kf[j], so the gradient of the SUM w.r.t. kf is the vector of derivatives dE_pred[j]/dkappa_j.
# torch.autograd.grad returns a tuple (one entry per input); (dE_pred,) = ... unpacks its single element.
(dE_pred,) = torch.autograd.grad(E_pred.sum(), kf)

fig, axes = plt.subplots(1, 3, figsize=(16, 4))
axes[0].plot(k_fine, E_fine, "k", lw=2, label="exact")
axes[0].plot(k_fine, E_pred.detach(), "--", label="network")
axes[0].plot(k_train, E_train, "o", color="C3", label="12 training points")
axes[0].set_ylabel(r"$E_0(\kappa)$"); axes[0].legend()
axes[1].semilogy(k_fine, np.abs(E_pred.detach().numpy() - E_fine))
axes[1].set_ylabel(r"$|E_0^{\rm net} - E_0^{\rm exact}|$")
axes[2].plot(k_fine, dE_fine, "k", lw=2, label="exact (Hellmann-Feynman)")
axes[2].plot(k_fine, dE_pred, "--", label="autograd of the network")
axes[2].set_ylabel(r"$dE_0/d\kappa$"); axes[2].legend()
for ax in axes: ax.set_xlabel(r"$\kappa$")
fig.tight_layout(); plt.show()
inside = (k_fine >= k_train.min()) & (k_fine <= k_train.max())     # between the smallest and largest training kappa
err_E, err_dE = np.abs(E_pred.detach().numpy() - E_fine), np.abs(dE_pred.numpy() - dE_fine)
print(f"training kappa from {k_train.min():.2f} to {k_train.max():.2f}")
print(f"max error of E0 :  inside {err_E[inside].max():.1e},  outside {err_E[~inside].max():.1e}")
print(f"max error of dE0:  inside {err_dE[inside].max():.1e},  outside {err_dE[~inside].max():.1e}")
# Between the smallest and largest training kappa (interpolation) the errors are much smaller than outside the
# sampled range (extrapolation, see Section 10). Inside, the derivative is less accurate than the energy itself:
# the loss contains only values of E0, nothing constrains the slope directly. The network has 25 parameters
# for 12 data points, so it can pass through all of them; the fit is nevertheless smooth here because E0(kappa)
# itself is smooth. (Adding the Hellmann-Feynman derivatives to the loss is known as Sobolev training.)

Exercise 5 (advanced) — Two dimensions

The UAT holds in any dimension. Fit \[g(x,y) = \sin(2x)\cos(y)\, e^{-(x^2+y^2)/4} \tag{29}\] on \([-3,3]^2\) (a \(30\times30\) grid of training points) with nn.Sequential(nn.Linear(2, N), nn.Tanh(), nn.Linear(N, 1)) for 8, 32 and 128 neurons, using Adam (lr=1e-2, 1500 steps; kept small for speed, 3000 or more steps give smaller errors). Here nn.Linear(n_in, n_out) is the affine map \(\mathbf W\mathbf x + \mathbf b\) from \(n_{\rm in}\) to \(n_{\rm out}\) components (with trainable \(\mathbf W\) and \(\mathbf b\)), and nn.Sequential chains the layers, applying them one after another. Show the target, the fit and the error as images (imshow), one row per \(N\). The first lines of the solution build the data (you may copy them): torch.meshgrid(xs, xs, indexing="xy") returns two \(30\times30\) arrays X, Y with the \(x\) and \(y\) coordinates of all grid points (with "xy" the rows correspond to \(y\), the layout that imshow expects), and reshape(-1) flattens them into lists of 900 points.

Solution

Code 
import torch.nn as nn
n_grid = 30
xs = torch.linspace(-3, 3, n_grid)
X, Y = torch.meshgrid(xs, xs, indexing="xy")
G = torch.sin(2 * X) * torch.cos(Y) * torch.exp(-(X**2 + Y**2) / 4)
inputs = torch.stack([X.reshape(-1), Y.reshape(-1)], dim=1)   # shape (900, 2): each row is a point (x, y)
targets = G.reshape(-1, 1)                                    # shape (900, 1)

fig, axes = plt.subplots(3, 3, figsize=(12, 11))
for row, N in enumerate([8, 32, 128]):
    torch.manual_seed(0)
    # nn.Linear creates its weights and biases with PyTorch's default random initialisation (scaled by 1/sqrt(n_in))
    net2d = nn.Sequential(nn.Linear(2, N), nn.Tanh(), nn.Linear(N, 1))
    opt = torch.optim.Adam(net2d.parameters(), lr=1e-2)
    for _ in range(1500):
        opt.zero_grad()
        L = torch.mean((net2d(inputs) - targets)**2)
        L.backward()
        opt.step()
    with torch.no_grad():
        F_net = net2d(inputs).reshape(n_grid, n_grid)
    for ax, img, title in zip(axes[row], [G, F_net, F_net - G],
                              ["target", f"network N = {N}", f"error, MSE = {L.item():.1e}"]):
        im = ax.imshow(img, origin="lower", extent=[-3, 3, -3, 3], cmap="RdBu_r")
        fig.colorbar(im, ax=ax, shrink=0.8)
        ax.set_title(title); ax.set_xlabel("$x$"); ax.set_ylabel("$y$")
fig.tight_layout(); plt.show()
# The error decreases from N = 8 to N = 32; beyond that the result is limited by the 1500 Adam steps, not by N
# (N = 32 and N = 128 give the same MSE).
