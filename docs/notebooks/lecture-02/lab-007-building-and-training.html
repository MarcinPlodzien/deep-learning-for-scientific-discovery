Lab 007 — Building and training networks

We assume familiarity with PyTorch tensors, the classes nn.Linear, nn.Sequential and nn.Module, and with how autograd computes gradients. This notebook combines them and treats in detail the two things that all neural-network code relies on: how a network is built, and how it is trained.

PyTorch offers two ways to build a network: the container nn.Sequential, which applies layers one after another, and a class derived from nn.Module, in which any computation can be expressed in a method forward. For a series of architectures of increasing size (Sections 3–6, called Examples A to D in the text and in the figures) we draw the network, build it in both ways, check that both give the same function, and follow the forward pass through the stored weight matrices. For the smallest network, Example A, a third construction with explicit parameters and einsum is added. We then construct networks automatically from a list of layer sizes (Section 7), build architectures that nn.Sequential cannot express (Section 8), and collect the tools used to inspect a model (Section 9).

The second half of the notebook takes the training loop apart line by line (Section 10): what each line does to the parameters and their gradients, first with the whole training set in every update, then with mini-batches and a validation set (Section 11). The loop is then packed into a reusable function that compares architectures and saves the chosen model (Section 12), the most common bugs are reproduced on purpose so that they can be recognised (Section 13), and finally the image classifier of Example D is trained on handwritten digits (Section 14). A summary (Section 15) and exercises with solutions (Section 16) close the notebook.

1. Composition of layers

A fully connected (dense) network with layer sizes \(n_0, n_1, \dots, n_L\) maps an input vector \(\mathbf x\) with \(n_0\) components to an output with \(n_L\) components through \[\mathbf h^{(0)} = \mathbf x,\qquad \mathbf h^{(l)} = \sigma\big(\mathbf W^{(l)}\mathbf h^{(l-1)} + \mathbf b^{(l)}\big),\quad l = 1,\dots,L-1,\qquad f(\mathbf x) = \mathbf W^{(L)}\mathbf h^{(L-1)} + \mathbf b^{(L)} . \tag{1}\] Here \(\mathbf W^{(l)}\) is a matrix of shape \(n_l\times n_{l-1}\) and \(\mathbf b^{(l)}\) a vector of length \(n_l\), so layer \(l\) has \[P_l = n_l(n_{l-1}+1) \tag{2}\] parameters. The activation function \(\sigma\) is applied element-wise, and only in the hidden layers. The last layer usually has no activation (regression), or one adapted to the task, for example the softmax for classification; in PyTorch the softmax is usually applied inside the loss function rather than as a layer (Section 14.2).

In PyTorch one layer, \[\mathbf h_{\rm out} = \mathbf W\mathbf h_{\rm in} + \mathbf b , \tag{3}\] is nn.Linear(n_in, n_out); it stores weight with shape (n_out, n_in) and bias with shape (n_out,). Data are processed in batches: an input tensor has shape (B, n_0), one row per sample, and the output has shape (B, n_L). For a batch the layer computes H_out = H_in @ W.T + b. The transpose appears because every sample is a row of H_in: the row form of equation (3) is \[\mathbf h_{\rm out}^T = \mathbf h_{\rm in}^T\mathbf W^T + \mathbf b^T , \tag{4}\] applied to all rows at once.

The list \([n_0, n_1, \dots, n_L]\) together with the choice of \(\sigma\) is the architecture of the network.

2. Drawing network architectures

Every architecture in this notebook is drawn with the following function. Each circle is a node (neuron), each grey line a weight. The function uses only basic plotting commands (plot, scatter, text). Layers with more than max_nodes nodes are drawn shortened, with “…” marking the omitted nodes. The parameter count in the title is equation (2) summed over the layers. The layer sizes passed to the function are read from the nn.Linear layers of the model by linear_sizes, defined in the same cell, so that a drawing always shows the network that was built; dense_parameter_count evaluates equation (2) summed over the layers, and an assert compares it with PyTorch’s own count.

Code 
def draw_network(layer_sizes, activations=None, title="", max_nodes=10, ax=None,
                 input_labels=None, output_labels=None):
    """
    Draw a fully connected network.
    layer_sizes : e.g. [1, 8, 1] = 1 input, one hidden layer with 8 nodes, 1 output
    activations : names of the activation functions of the hidden layers, e.g. ["tanh"]
    max_nodes   : larger layers are drawn with max_nodes nodes and a vertical "..." in the middle
    input_labels, output_labels : optional texts written next to the input and output nodes, e.g. ["$x$"]
    """
    if ax is None:
        fig, ax = plt.subplots(figsize=(1.9 * len(layer_sizes) + 1, 4.2))
    n_layers = len(layer_sizes)
    positions = []                                   # list of (x, y) arrays, one per layer
    for i, n in enumerate(layer_sizes):
        shown = min(n, max_nodes)
        y = np.linspace(-1, 1, shown) if shown > 1 else np.array([0.0])
        positions.append((np.full(shown, float(i)), y * min(1.0, shown / max_nodes + 0.15)))
    # connections between neighbouring layers
    for i in range(n_layers - 1):
        (x0, y0), (x1, y1) = positions[i], positions[i + 1]
        for a in y0:
            for b in y1:
                ax.plot([x0[0], x1[0]], [a, b], color="0.7", lw=0.6, zorder=1)
    # nodes and labels
    for i, (n, (xs, ys)) in enumerate(zip(layer_sizes, positions)):
        if i == 0:
            color, name = "C2", "input"
        elif i == n_layers - 1:
            color, name = "C3", "output"
        else:
            act = activations[i - 1] if activations is not None else ""
            color, name = "C0", f"hidden {i}" + (f"\n{act}" if act else "")
        ax.scatter(xs, ys, s=260, color=color, edgecolor="k", zorder=3)
        if n > max_nodes:                            # mark omitted nodes
            ax.text(xs[0] + 0.2, 0.0, "...", rotation=90, fontsize=14, va="center", ha="center",
                    bbox=dict(facecolor="white", edgecolor="none", pad=1), zorder=4)
        ax.text(xs[0], -1.35, f"{name}\n{n} node" + ("s" if n > 1 else ""), ha="center", va="top", fontsize=10)
    if input_labels is not None:
        for y, lab in zip(positions[0][1], input_labels):
            ax.text(-0.18, y, lab, ha="right", va="center", fontsize=12)
    if output_labels is not None:
        for y, lab in zip(positions[-1][1], output_labels):
            ax.text(n_layers - 1 + 0.18, y, lab, ha="left", va="center", fontsize=12)
    n_params = sum(n_in * n_out + n_out for n_in, n_out in zip(layer_sizes[:-1], layer_sizes[1:]))
    ax.set_title((title + "\n" if title else "") + f"layer sizes {layer_sizes},  {n_params} parameters", fontsize=11)
    ax.set_xlim(-0.8, n_layers - 0.2); ax.set_ylim(-2.1, 1.3)
    ax.axis("off")
    return ax

def linear_sizes(model):
    """Layer sizes [n_0, n_1, ..., n_L] of a dense network, read from its nn.Linear layers in the order of definition."""
    linear = [m for m in model.modules() if isinstance(m, nn.Linear)]
    return [linear[0].in_features] + [m.out_features for m in linear]

def dense_parameter_count(sizes):
    """Number of weights and biases of a dense network with these layer sizes."""
    return sum(n_out * (n_in + 1) for n_in, n_out in zip(sizes[:-1], sizes[1:]))

3. One hidden layer

The first architecture, Example A, is the network of the Universal Approximation Theorem from the lecture, \[f(x) = \sum_{i=1}^{N} W^{(2)}_{i}\,\tanh\big(W^{(1)}_{i} x + b^{(1)}_i\big) + b^{(2)}, \tag{5}\] with one input, one hidden layer of \(N\) nodes and one output, i.e. layer sizes \([1, N, 1]\). We take eight hidden nodes. Because it is so small, every number in it can be inspected, and we use it to compare the different ways of writing a network in PyTorch.

3.1 The container nn.Sequential

nn.Sequential(layer_1, layer_2, ...) stores the layers in order. Calling the model applies them one after another to the input. This is the shortest way to write a network whose computation is a plain chain of layers.

3.2 A class derived from nn.Module

The same network can be written as a class. In __init__ the layers are created and stored as attributes (this registers their parameters); forward describes the computation.

Code 
class OneHiddenLayer(nn.Module):
    """f(x) = W2 tanh(W1 x + b1) + b2  with N hidden nodes."""

    def __init__(self, n_hidden):
        super().__init__()                        # set up the internal bookkeeping of nn.Module
        self.hidden = nn.Linear(1, n_hidden)      # first layer: 1 -> n_hidden
        self.activation = nn.Tanh()
        self.output = nn.Linear(n_hidden, 1)      # second layer: n_hidden -> 1

    def forward(self, x):
        h = self.activation(self.hidden(x))       # hidden layer: shape (B, n_hidden)
        return self.output(h)                     # output: shape (B, 1)

torch.manual_seed(0)
model_cls = OneHiddenLayer(N)
print(model_cls)
for name, p in model_cls.named_parameters():
    print(f"{name:15s} shape {tuple(p.shape)}")

  (hidden): Linear(in_features=1, out_features=8, bias=True)

3.3 Equivalence of the two constructions

The two models were initialised with the same random seed, and the layers were created in the same order, so they even start with the same random numbers. To make the comparison independent of this, we copy the parameters of model_seq into model_cls explicitly and compare the outputs.

a.copy_(b) writes the values of b into the existing tensor a (the trailing underscore marks a method that changes the tensor in place). An assignment model_cls.hidden.weight = model_seq[0].weight would not copy anything: both models would then share one and the same tensor, and training one of them would change the other.

Code 
with torch.no_grad():                                   # copying values is not part of any gradient computation
    model_cls.hidden.weight.copy_(model_seq[0].weight)
    model_cls.hidden.bias.copy_(model_seq[0].bias)
    model_cls.output.weight.copy_(model_seq[2].weight)
    model_cls.output.bias.copy_(model_seq[2].bias)

x = torch.linspace(-3, 3, 200).reshape(-1, 1)           # a batch of 200 inputs, shape (200, 1)
with torch.no_grad():
    y_seq, y_cls = model_seq(x), model_cls(x)
print("input shape :", tuple(x.shape), "  output shape:", tuple(y_seq.shape))
print("max |difference| between the two models:", (y_seq - y_cls).abs().max().item())

3.4 The forward pass from the stored matrices

The model hides nothing: the same output follows from the stored matrices and the formula of Section 1. The argument of the activation, \(W^{(1)}_i x + b^{(1)}_i\), is called the pre-activation of node \(i\). In the left panel, ax.plot(x, h) receives an array h with \(N\) columns; matplotlib then draws one curve per column, i.e. one curve per hidden node.

Code 
W1, b1 = model_seq[0].weight, model_seq[0].bias        # shapes (N, 1) and (N,)
W2, b2 = model_seq[2].weight, model_seq[2].bias        # shapes (1, N) and (1,)
with torch.no_grad():
    pre_activation = x @ W1.T + b1                      # (200, 1) @ (1, N) + (N,)  ->  (200, N)

Each curve on the left is a smoothed step \(\tanh(W_i x + b_i)\) centred at \[x_i^\ast = -b_i/W_i ; \tag{6}\] \(|W_i|\) sets its steepness and the sign of \(W_i\) its direction. The initial weights are small (of magnitude at most 1), so the steps are gentle, and a node with \(W_i\) close to zero is almost constant (two such nodes appear here). The output on the right is the sum of these curves with the weights \(W^{(2)}_i\), plus \(b^{(2)}\). Training will move the centres, steepnesses and weights.

3.5 Explicit parameters and einsum

A third style writes the parameters as nn.Parameter tensors and the forward pass as index formulas with torch.einsum. For a batch \(x_{b}\) the layer formulas read \[h_{bj} = \tanh\Big(\sum_i x_{bi} W^{(1)}_{ji} + b^{(1)}_j\Big), \qquad f_{bk} = \sum_j h_{bj}W^{(2)}_{kj} + b^{(2)}_k , \tag{7}\] which einsum takes literally: "bi,ji->bj" (sum over \(i\), keep the batch index \(b\)).

This is still a class derived from nn.Module; what changes is that nothing is hidden in nn.Linear. The price is that the initialisation must be written out explicitly: below, PyTorch’s default for nn.Linear is reproduced (uniform in \([-1/\sqrt{n_{\rm in}}, 1/\sqrt{n_{\rm in}}]\) for weights and biases). The factor \(1/\sqrt{n_{\rm in}}\) keeps the weighted sums of equation (7) over the \(n_{\rm in}\) inputs of a layer of order one whatever the width of the layer, so that the \(\tanh\) nodes start neither saturated nor all near zero.

Two functions appear here for the first time. torch.empty(n, m) reserves memory for a tensor of shape (n, m) without setting its values (the entries are whatever was in memory). .uniform_(a, b) then overwrites the entries, in place, with random numbers distributed uniformly in \([a, b]\).

Code 
class OneHiddenLayerEinsum(nn.Module):
    # f(x) = W2 tanh(W1 x + b1) + b2, written with explicit parameters and einsum

    def __init__(self, n_hidden, n_in=1, n_out=1):
        super().__init__()
        bound1, bound2 = 1 / n_in**0.5, 1 / n_hidden**0.5
        # nn.Parameter registers a tensor as trainable; uniform_(a, b) fills it with uniform random numbers
        self.W1 = nn.Parameter(torch.empty(n_hidden, n_in).uniform_(-bound1, bound1))     # (N, n_in), as in nn.Linear
        self.b1 = nn.Parameter(torch.empty(n_hidden).uniform_(-bound1, bound1))           # (N,)
        self.W2 = nn.Parameter(torch.empty(n_out, n_hidden).uniform_(-bound2, bound2))    # (n_out, N)
        self.b2 = nn.Parameter(torch.empty(n_out).uniform_(-bound2, bound2))              # (n_out,)

    def forward(self, x):                                   # x: (B, n_in)
        h = torch.tanh(torch.einsum("bi,ji->bj", x, self.W1) + self.b1)    # h_bj = tanh(sum_i x_bi W1_ji + b1_j)
        return torch.einsum("bj,kj->bk", h, self.W2) + self.b2             # f_bk = sum_j h_bj W2_kj + b2_k

model_ein = OneHiddenLayerEinsum(N)
print("parameters:", [(name, tuple(p.shape)) for name, p in model_ein.named_parameters()])

All three constructions give the same function. The one with explicit parameters is useful for teaching (the code is the formula), for operations that are not a plain matrix product (contractions over several axes, e.g. in attention layers of transformers or in tensor-network models used in physics), and for layers with unusual parameter shapes. For ordinary dense layers nn.Linear is preferable: it is equally fast (for such products einsum calls the same matrix-multiplication routine), shorter, and its initialisation is handled by PyTorch.

The network is untrained: its parameters are random, so \(f(x)\) is a random smooth function. Training (Section 10) changes the parameters so that \(f\) approximates data.

All kinds of models are used in exactly the same way afterwards: model(x), model.parameters(), training. The choice between them therefore depends only on how the data flow through the model; Section 8.3 discusses it in detail.

Code 
class MLPEinsum(nn.Module):
    def __init__(self, layer_sizes):
        super().__init__()
        self.weights, self.biases = nn.ParameterList(), nn.ParameterList()   # lists that register their parameters
        for n_in, n_out in zip(layer_sizes[:-1], layer_sizes[1:]):
            bound = 1 / n_in**0.5
            self.weights.append(nn.Parameter(torch.empty(n_out, n_in).uniform_(-bound, bound)))
            self.biases.append(nn.Parameter(torch.empty(n_out).uniform_(-bound, bound)))

    def forward(self, h):
        n_layers = len(self.weights)
        for l, (W, b) in enumerate(zip(self.weights, self.biases)):
            h = torch.einsum("bi,ji->bj", h, W) + b          # the same formula for every layer
            if l < n_layers - 1:                              # no activation after the last layer
                h = torch.tanh(h)
        return h

6.2 Classifier architecture

The network for these images is that of the lecture: a \(28\times28\) image is flattened to a vector of \(784\) pixel values, followed by two hidden layers with ReLU and \(10\) outputs, one per class. The outputs are arbitrary real numbers (logits); softmax turns them into probabilities \(q_0, \dots, q_9\), which are compared with the true label by the cross-entropy (lecture). The predicted class is the one with the largest probability (argmax). nn.Flatten() is a layer without parameters that reshapes (B, 28, 28) into (B, 784).

The pixel values are divided by 255 and converted to floating-point numbers (.float()), so that the inputs lie in \([0, 1]\): inputs of order one (the default initialisation of nn.Linear assumes inputs of order one; Section 10.1 explains what happens otherwise).

Two choices differ from Examples A–C. The first is the activation: the rectified linear unit, \[\mathrm{ReLU}(z) = \max(0, z) , \tag{10}\] replaces \(\tanh\). It is cheap to compute and does not saturate for positive \(z\), which makes it the standard choice for classifiers and deep networks. A ReLU network is piecewise linear in its input; for regression of smooth physical functions (Examples A–C, Section 10) \(\tanh\) is preferred, because the fitted function is then smooth and can be differentiated any number of times. The second choice is the widths 128 and 64. They are illustrative; widths of order 10–1000 are all in use for this task. Decreasing widths (784, 128, 64, 10), which compress the input gradually, are a common convention but not a requirement. The same holds for the widths 8, 16 and 32 in Examples A–C.

7. Building networks automatically from a list of layer sizes

Writing every layer out explicitly is error-prone for deep networks. Since a dense network is determined by the list \([n_0, \dots, n_L]\) and the activation, the layers can be created in a loop.

7.1 With nn.Sequential

nn.Sequential(*layers) accepts a Python list of layers; the star unpacks the list into separate arguments.

Code 
def make_mlp(layer_sizes, activation=nn.Tanh):
    """Dense network with the given layer sizes; `activation` (a class such as nn.Tanh) after every hidden layer."""
    layers = []
    for i in range(len(layer_sizes) - 1):
        n_in, n_out = layer_sizes[i], layer_sizes[i + 1]
        layers.append(nn.Linear(n_in, n_out))
        is_last_layer = (i == len(layer_sizes) - 2)
        if not is_last_layer:                     # no activation after the output layer
            layers.append(activation())           # a new activation object for every layer
    return nn.Sequential(*layers)

7.2 With a class and nn.ModuleList

In a class, a variable number of layers is stored in an nn.ModuleList, a list that registers the parameters of its elements. The loop over the layers then sits in forward. This form is useful when forward has to do something between the layers (Section 8).

The argument activation has a different form in the two constructions. make_mlp receives a class (nn.Tanh) and creates a new layer object activation() for every position in the chain, because nn.Sequential accepts only layer objects. In forward of the class below any function can be called directly, so the function torch.tanh is passed.

Code 
class MLP(nn.Module):
    def __init__(self, layer_sizes, activation=torch.tanh):
        super().__init__()
        self.layers = nn.ModuleList(
            [nn.Linear(n_in, n_out) for n_in, n_out in zip(layer_sizes[:-1], layer_sizes[1:])]
        )
        self.activation = activation

    def forward(self, x):
        for layer in self.layers[:-1]:            # all layers except the last one
            x = self.activation(layer(x))
        return self.layers[-1](x)                 # last layer without activation

8. Architectures beyond nn.Sequential

8.1 A skip (residual) connection

In a residual layer the input is added to the output: \[\mathbf h \;\mapsto\; \mathbf h + \tanh(\mathbf W\mathbf h + \mathbf b) . \tag{13}\] Such connections make very deep networks trainable (residual networks, ResNets). The addition of the input cannot be expressed as a chain of layers, so a class is needed.

Code 
class ResidualMLP(nn.Module):
    """input layer -> n_blocks residual blocks of width `width` -> output layer."""

    def __init__(self, n_in, width, n_blocks, n_out):
        super().__init__()
        self.input_layer = nn.Linear(n_in, width)
        self.blocks = nn.ModuleList([nn.Linear(width, width) for _ in range(n_blocks)])
        self.output_layer = nn.Linear(width, n_out)

    def forward(self, x):
        h = torch.tanh(self.input_layer(x))
        for block in self.blocks:
            h = h + torch.tanh(block(h))          # skip connection: the input of the block is added to its output
        return self.output_layer(h)

8.2 A physics constraint built into the network

A wavefunction of a particle in a box \([0, 1]\) must vanish at both walls, at 0 and at 1. An unconstrained network \(\mathrm{NN}(x)\) does not satisfy this, but the ansatz \[\psi(x) = x\,(1-x)\,\mathrm{NN}(x) \tag{14}\] does, for every value of the parameters. The boundary conditions are then never violated during training. The network inside can be any model, e.g. one made with make_mlp.

Code 
class BoxWavefunction(nn.Module):
    """psi(x) = x (1 - x) NN(x): vanishes at x = 0 and x = 1 for any parameters of NN."""

    def __init__(self, layer_sizes):
        super().__init__()
        self.net = make_mlp(layer_sizes)          # a network inside a network: its parameters are registered as well

    def forward(self, x):
        return x * (1 - x) * self.net(x)

psi = BoxWavefunction([1, 16, 16, 1])
x_box = torch.linspace(0, 1, 101).reshape(-1, 1)
with torch.no_grad():
    values = psi(x_box)
print("psi(0) =", values[0].item(), "  psi(1) =", values[-1].item())
print("parameters:", sum(p.numel() for p in psi.parameters()), "(all inside psi.net)")

8.3 Choice between nn.Sequential and a class

nn.Sequential describes exactly one kind of computation: one input tensor passes through a fixed chain of layers, and the output of each layer is the input of the next one. Whenever the computation can be drawn as such a chain, nn.Sequential is the shortest and clearest choice. For everything else a class with a forward method is needed, because forward can contain arbitrary Python code. The table lists typical situations.

situation nn.Sequential class
chain of layers, one input, one output yes yes (longer)
a layer is skipped or its input is added to its output (skip connection, 8.1) no yes
a fixed formula around the network, e.g. a physical constraint (8.2) no yes
the same layer (same weights) is used several times, e.g. to enforce a symmetry no yes
several inputs (e.g. a position and a parameter) or several outputs treated differently no yes
intermediate results are needed (e.g. for analysis) only by looping over the layers explicitly yes, returned by forward
a trainable number that is not part of any layer (nn.Parameter) no yes
if statements or loops in the computation no yes

In practice the two are combined: the chain-like parts of a model are written as nn.Sequential blocks (or built with make_mlp), and a class connects them. The following class shows several items of the table at once: an even wavefunction \[\psi(x) = A\,[\,g(x) + g(-x)\,], \qquad \psi(-x) = \psi(x), \tag{15}\] where the same network \(g\) is applied twice (the shared weights enforce the symmetry), \(A\) is a trainable number outside any layer, and forward can also return the intermediate values \(g(\pm x)\).

Code 
class EvenFunction(nn.Module):
    # psi(x) = A * (g(x) + g(-x)): even in x for any parameters of g and any A

    def __init__(self, layer_sizes):
        super().__init__()
        self.g = make_mlp(layer_sizes)                 # a Sequential block inside the class
        self.amplitude = nn.Parameter(torch.ones(1))   # a trainable number that is not part of any layer;
                                                       # it starts at 1 (any non-zero value works, it is trained)

    def forward(self, x, return_parts=False):
        g_plus = self.g(x)                             # the same network (same weights) ...
        g_minus = self.g(-x)                           # ... applied a second time
        psi = self.amplitude * (g_plus + g_minus)
        if return_parts:                               # ordinary Python control flow
            return psi, g_plus, g_minus
        return psi

9. Inspecting a model

Three tools are used constantly. named_parameters() returns the names and tensors of all trainable parameters; state_dict() returns a dictionary from names to tensors with all parameters, which is what is saved to disk (Section 12); and passing a batch through the layers one by one while printing the shapes is the quickest way to find shape errors. def summary(model, x):
    """Print the output shape and the number of parameters of every layer of an nn.Sequential model for the input batch x."""
    print(f"{'layer':35s} {'output shape':15s} parameters")
    print(f"{'input':35s} {str(tuple(x.shape)):15s}")

        total += n

    print(f"total parameters: {total}")

torchinfo and torchview

The function summary above works only for an nn.Sequential, because it runs over the layers in order. Two libraries do the same for any model. The drawing function of Section 2 shows neurons and weights; these libraries show layers and shapes, which is the only readable view of large models.

The library torchinfo prints a table of the layers. torchinfo.summary(model, input_size=...) passes a batch of zeros of the given shape through the model and records, for every layer, the shape of its output and the number of its parameters; the lines at the bottom give the totals and an estimate of the memory needed. The first number of input_size is the batch size: it appears as the first dimension of every output shape and does not change the parameter counts. The library torchview passes the same kind of batch through the model and draws the layers as a graph in which every box is one layer with the shapes of its input and output; with expand_nested=True a submodule that itself contains layers, such as an nn.Sequential block called inside a larger model, is drawn as a frame around its layers. The graph is rendered by the program Graphviz to a PNG (Portable Network Graphics) file.

The three views serve different purposes. The neuron-level drawing explains what a dense layer is but is practical only for small dense networks. The torchinfo table is the quickest check of shapes and parameter counts and the first thing to print when a model raises a shape error. The torchview graph shows how the layers are connected, which matters as soon as the data flow is not a single chain, for example with skip connections or several inputs.

10. The training loop in detail

10.1 Damped-oscillation data

We simulate a measurement of a damped oscillation, \[y(t) = e^{-0.2t}\cos(2t), \qquad t\in[0, 10], \tag{17}\] at \(K\) random times, 200 of them, with Gaussian noise of standard deviation \(0.05\). The data are split at random into three parts with different roles. The training set (120 points) is used to change the parameters. The validation set (40 points) is used to monitor training and to make choices (architecture, learning rate, number of epochs): the parameters never see it, but our decisions do. The test set (40 points) is used once, at the very end, to estimate how well the final model works on new data; because no decision was based on it, this estimate is not biased by our choices.

The fractions 60 / 20 / 20 % are a convention; splits between about 60–80 % for training and 10–20 % each for validation and test are common. The exact values are not critical, but the validation and test sets must contain enough points for their mean losses to be meaningful averages. The noise level \(0.05\) is also arbitrary: small compared with the amplitude 1 of the signal, but large enough to be visible in the plot.

Two practical details matter. PyTorch layers expect inputs of shape (B, n_in), here (B, 1), and the targets must have the same shape as the outputs, (B, 1). Moreover, the input \(t\), which lies in \([0, 10]\), is rescaled to \([-1, 1]\). With one input, the default initialisation of nn.Linear draws the first-layer weights and biases uniformly from \([-1, 1]\) (the bound \(1/\sqrt{n_{\rm in}}\) is 1), so the pre-activations \(W t + b\) are of order \(|t|\). For times of order 10 most of them would lie far in the flat part of \(\tanh\) (\(\tanh 3\) is already about 0.995): these nodes would start saturated, their gradients would be small, and training would slow down (Section 13.4 shows the effect).

Two new operations appear in the code. torch.randperm(K) returns the integers \(0, \dots, K-1\) in random order; the first 120 of them become the training indices, and so on. It receives its own random-number generator torch.Generator().manual_seed(0), so that the split is reproducible and does not depend on how many random numbers were drawn earlier in the notebook. X_all[train_idx], indexing with a tensor of integers, selects the rows with these indices in this order; since inputs and targets are indexed with the same indices, every input stays paired with its target.

Code

    return np.exp(-0.2 * t) * np.cos(2 * t)

10.2 Model, loss function and optimiser

Training needs three objects. The model is make_mlp([1, 32, 32, 1]). The loss function nn.MSELoss() computes the mean squared error (MSE) for a batch, \[\mathcal L = \frac1B\sum_i (f(x_i) - y_i)^2 , \tag{18}\] equivalent to torch.mean((pred - y)**2). The optimiser is an object from torch.optim that holds references to the parameters and implements the update rule.

Two hidden layers of 32 nodes are a modest size for a one-dimensional function with about three periods of oscillation on the interval; Section 12 compares this choice with smaller and larger networks. The learning rate 0.1 of stochastic gradient descent (SGD, torch.optim.SGD; here used with the full training set, i.e. as plain gradient descent) is arbitrary: only a single step is performed, to check the update rule, and any value would serve. torch.manual_seed(1) immediately before the model is created fixes its initial parameters, so that the runs below start from the same point and can be compared; the value of the seed is arbitrary.

Code 
torch.manual_seed(1)
model = make_mlp([1, 32, 32, 1])
loss_fn = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)     # plain gradient descent first, to check the update rule

10.3 One training step in slow motion

One step consists of five lines. We follow three of the parameters (the first three biases of the first layer) and their gradients through the step, and check that optimizer.step() for SGD is exactly the update \[\theta \;\leftarrow\; \theta - \eta\,\frac{\partial\mathcal L}{\partial\theta} , \tag{19}\] where \(\theta\) is any parameter, \(\mathcal L\) the loss and \(\eta\) the learning rate (lr).

Code 
p = model[0].bias                                   # a parameter tensor of shape (32,); we print its first 3 entries
print("before the step:     p[:3] =", p[:3].detach().numpy(), "  p.grad =", p.grad)

# 1) forward pass: predictions for the whole training set
pred = model(X_train)                               # shape (120, 1)
# 2) loss: a single number (a tensor with one element) that depends on all parameters
loss = loss_fn(pred, Y_train)
print("loss:", loss.item())
# 3) reset the gradients stored from a previous step (here there are none yet, but this line is always needed)
optimizer.zero_grad()
# 4) backward pass: compute d loss / d parameter for every parameter, stored in .grad
loss.backward()
print("after backward():    p.grad[:3] =", p.grad[:3].numpy())
p_old, grad_old = p.detach().clone(), p.grad.clone()  # copies, for the check below
# 5) update the parameters with the rule of the optimiser
optimizer.step()
print("after step():        p[:3] =", p[:3].detach().numpy())
print("p_old - lr * grad:         ", (p_old - 0.1 * grad_old)[:3].numpy())
print("max |difference|:", (p.detach() - (p_old - 0.1 * grad_old)).abs().max().item())

Before the first backward() no gradient has been computed, so p.grad is None rather than a tensor of zeros. The copies p_old, grad_old are made with clone() because optimizer.step() changes p in place: without clone(), p_old would be a second name for the same memory and would change together with p. detach() excludes the copy from the gradient computation.

The optimiser changed every parameter by \(-\eta\times\) its gradient, as gradient descent prescribes. More advanced optimisers (momentum, Adam) use the same .grad tensors but a different update rule.

10.4 Full-batch training loop

Repeating the five lines gives the training loop. In every iteration we also compute the validation loss, inside torch.no_grad() (no gradients are needed for monitoring, which saves memory and time). We use Adam (adaptive moment estimation, an optimiser that adapts the step size of every parameter using running averages of its gradients; see the lecture), which converges faster here.

The learning rate \(10^{-2}\) is a common starting value for Adam on small problems. In this example values between about \(3\cdot10^{-3}\) and \(3\cdot10^{-2}\) bring the training loss to the noise level within 2000 steps; with \(10^{-3}\) the loss decreases more slowly and reaches the noise level only near the end of the 2000 steps, and with \(10^{-1}\) the loss fluctuates from step to step. With \(10^{-2}\) the training loss is within a few per cent of its final value after about 1000 steps; the number of steps, 2000, leaves a margin and is otherwise arbitrary.

Code 
torch.manual_seed(1)
model = make_mlp([1, 32, 32, 1])
optimizer = torch.optim.Adam(model.parameters(), lr=1e-2)
n_steps = 2000
train_hist, val_hist = [], []

t0 = time.perf_counter()
for step in range(n_steps):
    pred = model(X_train)                         # 1) forward
    loss = loss_fn(pred, Y_train)                 # 2) loss
    optimizer.zero_grad()                         # 3) reset gradients
    loss.backward()                               # 4) backward
    optimizer.step()                              # 5) update

    with torch.no_grad():                         # monitoring only
        val_loss = loss_fn(model(X_val), Y_val)
    train_hist.append(loss.item())
    val_hist.append(val_loss.item())

The training loss decreases to about the variance of the noise, \[\sigma^2 = 0.05^2 = 2.5\cdot10^{-3} : \tag{20}\] the remaining error is the noise in the data, which no model can predict. Indeed, if the network were exactly the true function \(g\), then \[f(t_i) - y_i = g(t_i) - (g(t_i) + \varepsilon_i) = -\varepsilon_i , \tag{21}\] and the mean of \(\varepsilon_i^2\) over many points is the variance of equation (20). A training loss far below \(\sigma^2\) would mean that the network reproduces the noise itself. The validation loss is somewhat larger (printed above): with only 120 training points the network also fits part of the noise of these particular points, which does not carry over to new points. The difference between training and validation loss measures this effect; it becomes large when a network overfits.

11. Mini-batches, epochs and validation

11.1 Mini-batches

For large data sets the full-batch loss is too expensive to compute in every step. The training set is then split into mini-batches; every step uses one mini-batch, and one pass over all mini-batches is an epoch. The gradient of a mini-batch is a noisy estimate of the full gradient (this is stochastic gradient descent). PyTorch provides two helpers: TensorDataset(X, Y) pairs inputs with targets, and DataLoader(dataset, batch_size=..., shuffle=True) returns the mini-batches of one epoch, in a new random order every epoch.

The batch size is a free choice; powers of two between 16 and 256 are customary. Smaller batches give noisier gradients and more updates per epoch, larger batches the opposite. Here 32 is chosen so that an epoch of 120 samples consists of a few (four) steps.

11.2 Training loop with mini-batches

The five lines are the same; they are now inside a loop over the mini-batches, which is inside a loop over the epochs. The training loss of an epoch is the plain average of its mini-batch losses (np.mean(batch_losses)). It is collected while the parameters are still changing and it gives the shorter last batch (24 samples) the same weight as the others, so it differs slightly from the loss of the final model on the full training set.

model.train() and model.eval() switch layers such as dropout and batch normalisation (introduced later in the course) between their training and evaluation behaviour. Our model has no such layers, so the calls change nothing here, but they belong to the standard loop.

12. Model comparison, saving and loading

The loop of Section 11.2 is now written once as a reusable function and used to compare four architectures trained on the same data. They span almost three orders of magnitude in the number of parameters (13 to 8513), from too small to more than enough; any similar sequence shows the same trend. The default n_epochs=300 (1200 updates) is smaller than the 2000 updates of Sections 10–11 to keep the comparison fast.

Code 
def train(model, X_train, Y_train, X_val, Y_val, n_epochs=300, batch_size=32, lr=1e-2, seed=0):
    """Train `model` with Adam and mini-batches; return the training and validation loss per epoch."""
    torch.manual_seed(seed)                                    # reproducible shuffling of the mini-batches
    loader = DataLoader(TensorDataset(X_train, Y_train), batch_size=batch_size, shuffle=True)
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)
    loss_fn = nn.MSELoss()
    history = {"train": [], "val": []}
    for epoch in range(n_epochs):
        model.train()
        batch_losses = []
        for xb, yb in loader:
            loss = loss_fn(model(xb), yb)
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
            batch_losses.append(loss.item())
        model.eval()
        with torch.no_grad():
            history["val"].append(loss_fn(model(X_val), Y_val).item())
        history["train"].append(np.mean(batch_losses))
    return history

The four bugs below are reproduced on purpose, because none of them stops the program: they are recognised only by their symptoms.

13.1 Output and target of different shapes

The model returns shape (B, 1). If the targets have shape (B,), broadcasting turns pred - y into a (B, B) matrix of all pairwise differences. nn.MSELoss only warns; an explicit torch.mean((pred - y)**2) does not even warn. The loss value is wrong and training fits the wrong objective.

Python’s module warnings normally prints a warning once and does not pass it to the program. To show the message in the output below, it is captured: warnings.catch_warnings(record=True) collects the warnings raised inside the with block into the list w, and simplefilter("always") makes sure the warning is recorded even if the same warning was shown before.

13.2 Forgetting optimizer.zero_grad()

Gradients accumulate in .grad. Without resetting them, .grad holds the sum of all gradients computed so far: it grows from step to step, and the updates no longer follow the gradient of the current loss. Below, the Adam training of Section 10.4, shortened to 1000 steps, once with and once without zero_grad(); we also print the norm of the gradient stored in the first layer at the end, and the cosine of the angle between the stored gradient (all parameters joined into one vector) and the true gradient of the current loss, computed separately with torch.autograd.grad. A cosine of \(+1\) means the same direction, \(-1\) the opposite one.

Code

    m = make_mlp([1, 32, 32, 1])

Without zero_grad() the stored gradient becomes much larger than the true gradient (in a re-run, about two orders of magnitude; the true gradient is itself large because the loss is large), and the loss grows instead of decreasing. The first-layer norms printed above (\(2\cdot10^{2}\) against \(10^{-4}\)) compare the two runs, not the stored and the true gradient of the same run. The size alone would not harm Adam much, since Adam divides each update by a running average of the gradient size. The harm comes from the direction: the stored .grad is the sum of all past gradients, dominated by the old ones, and no longer follows the gradient of the current loss. At the end of this run the cosine printed above is close to \(-1\): the updates point uphill. (With zero_grad() the cosine is positive but below 1 because the stored gradient belongs to the parameters before the last step(), while the true gradient is computed after it.) No error is raised; only the loss curve reveals the bug.

14.2 Loss function and accuracy

For classification the loss is the cross-entropy (lecture). For one image with true class \(y\) and predicted probabilities \(q_k\) from the softmax (11), \[\ell = -\log q_y , \tag{22}\] the negative logarithm of the probability that the network gives to the correct class: it vanishes when this probability is 1 and grows without bound as the probability goes to zero. The loss of a batch is the mean over its images.

nn.CrossEntropyLoss() (stored as ce_loss, so that loss_fn, the MSE loss of Section 10 used again in the exercises, is not overwritten) takes the logits of shape (B, 10) and the labels as integers of shape (B,) (dtype int64, which labels already has); it applies the softmax itself, so the model must not end with a softmax layer. The label is used as an index: it picks \(q_y\) out of the ten probabilities.

The accuracy, the fraction of correctly classified images, is what we are interested in, but it cannot be used as a loss: it changes only when an image switches class, so its gradient with respect to the parameters is zero almost everywhere. The cross-entropy changes smoothly with the parameters.

A check before training: an untrained network gives probabilities of about 1/10 for every class (Section 6), so the loss should be close to \[\ell \approx -\log\tfrac{1}{10} = \ln 10 \approx 2.30 . \tag{23}\]

def accuracy(logits, y):
    """Fraction of images whose largest logit is at the true class."""
    return (logits.argmax(dim=1) == y).float().mean().item()

14.3 Training loop for the classifier

The loop is that of Section 11 with mini-batches, written out here because the loss and the recorded quantities differ. Mini-batches of 64 images are drawn in a new random order in every epoch (torch.randperm), and the optimiser is Adam with learning rate \(10^{-3}\), the default of Adam; 64 is a common batch size, and values from 32 to 256 work as well. After every epoch the loss and accuracy on the training and validation sets are computed for all images at once, inside torch.no_grad() (Section 10.4). The training loss is evaluated after the epoch, with the final parameters of that epoch, so that it can be compared with the validation loss. We train for 10 epochs (10 passes over the 50 000 training images). One epoch takes about a second on a CPU (central processing unit); the number is chosen so that the cell runs in about ten seconds and shows where the validation loss stops improving.

Both losses fall quickly during the first epochs. As training continues, the network gets a few more images right, but it also becomes more confident everywhere, and pays a large loss \(-\log q_y\) for every image on which it is confidently wrong.

15. Summary

A dense network is defined by its layer sizes \([n_0,\dots,n_L]\) and its activation; layer \(l\) has a weight matrix of shape \(n_l\times n_{l-1}\) and a bias vector of length \(n_l\). nn.Sequential(...) builds a chain of layers, while a class derived from nn.Module, with the layers created in __init__ and the computation defined in forward, builds any architecture. Both are used in the same way: model(x), model.parameters(), model.state_dict(). Networks of arbitrary depth are built in a loop, either as a list of layers passed to nn.Sequential(*layers) or as an nn.ModuleList in a class, but never as a plain Python list, whose parameters the model does not see.

A training step consists of the forward pass, the loss, zero_grad(), backward() and step(). Mini-batches come from a DataLoader, and one epoch is one pass over the training data. The data are divided into three sets: the training set fits the parameters, the validation set is used to monitor training and to choose between models, and the test set gives the final estimate and is used once. The validation loss is monitored inside torch.no_grad(), model.train() and model.eval() switch between the two behaviours of layers such as dropout, and a trained model is saved with torch.save(model.state_dict(), ...). Most silent bugs come from shapes ((B, 1) against (B,)), data types (float32) and the scale of the inputs. For classification (Section 14) the network has one output per class, nn.CrossEntropyLoss is applied to the logits with integer labels, and the model is evaluated by its accuracy and its confusion matrix.

Exercise 3 — A classification task

Points \((x, y)\) belong to class 0 if their distance from the origin is below 1 and to class 1 if it is between 1.3 and 2 (two rings, no point in between). 1. Generate 600 points of each class (sample the radius uniformly in the ring and the angle uniformly), shuffle them and split 800 / 200 / 200. 2. Train make_mlp([2, 16, 16, 2]) (two outputs = two class scores) with nn.CrossEntropyLoss, which takes the scores of shape (B, 2) and the integer labels of shape (B,) (dtype torch.long), and applies softmax internally. One score per class (rather than a single output) makes the same code work for any number of classes. The labels are integers because the loss uses them as indices, to pick the score of the correct class. Use Adam, lr=1e-2, full batch, 300 steps; record training and validation loss. 3. Report the accuracy (fraction of correctly classified points) on the validation and, at the end, on the test set. 4. Plot the decision boundary: the predicted class on a grid of points, with the data on top.

(The function train of Section 12 uses nn.MSELoss; write the training loop explicitly here.)

Solution

Code 
# 1) data: two rings
rng3 = np.random.default_rng(2)
def ring(n, r_min, r_max):
    r = rng3.uniform(r_min, r_max, n)
    phi = rng3.uniform(0, 2 * np.pi, n)
    return np.stack([r * np.cos(phi), r * np.sin(phi)], axis=1)

points_rings = np.concatenate([ring(600, 0.0, 1.0), ring(600, 1.3, 2.0)])
labels_rings = np.concatenate([np.zeros(600), np.ones(600)])
order = rng3.permutation(1200)                                      # shuffle points and labels together
Xc = torch.tensor(points_rings[order], dtype=torch.float32)
Yc = torch.tensor(labels_rings[order], dtype=torch.long)                  # integer class labels, shape (1200,)
Xc_train, Xc_val, Xc_test = Xc[:800], Xc[800:1000], Xc[1000:]
Yc_train, Yc_val, Yc_test = Yc[:800], Yc[800:1000], Yc[1000:]

# 2) model and training loop
torch.manual_seed(0)
clf_rings = make_mlp([2, 16, 16, 2])                                      # outputs: one score (logit) per class
ce_loss_rings = nn.CrossEntropyLoss()
opt = torch.optim.Adam(clf_rings.parameters(), lr=1e-2)
hist_tr, hist_va = [], []
for step in range(300):
    loss = ce_loss_rings(clf_rings(Xc_train), Yc_train)                         # scores (800, 2) vs labels (800,)
    opt.zero_grad(); loss.backward(); opt.step()
    with torch.no_grad():
        hist_va.append(ce_loss_rings(clf_rings(Xc_val), Yc_val).item())
    hist_tr.append(loss.item())

# 3) accuracy: the predicted class is the one with the larger score.
# argmax(dim=1) gives, for every row, the index of the largest entry. Softmax does not change the order of the
# scores, so this is also the class of highest probability, and softmax need not be computed.
# (... == Y) is a tensor of True/False; .float() turns it into 1.0/0.0, and its mean is the fraction of correct answers.
def accuracy_of(model, X, Y):
    with torch.no_grad():
        return (model(X).argmax(dim=1) == Y).float().mean().item()
print(f"validation accuracy: {accuracy_of(clf_rings, Xc_val, Yc_val):.3f}")
print(f"test accuracy (computed once at the end): {accuracy_of(clf_rings, Xc_test, Yc_test):.3f}")
# The two classes are separated by an empty ring (1 < r < 1.3), so a perfect classification is possible.
# Without the gap (e.g. class 1 for 1 < r < 2) points near r = 1 would be harder, and the accuracy would drop below 1.

# 4) decision boundary
g = np.linspace(-2.2, 2.2, 200)
GX, GY = np.meshgrid(g, g)
grid = torch.tensor(np.stack([GX.ravel(), GY.ravel()], axis=1), dtype=torch.float32)
with torch.no_grad():
    pred_class = clf_rings(grid).argmax(dim=1).numpy().reshape(200, 200)

fig, axes = plt.subplots(1, 2, figsize=(13, 5))
axes[0].plot(hist_tr, label="training"); axes[0].plot(hist_va, label="validation")
axes[0].set_yscale("log"); axes[0].set_xlabel("step"); axes[0].set_ylabel("cross-entropy"); axes[0].legend()
# the classes are the integers 0 and 1: boundaries at -0.5, 0.5, 1.5 give exactly one colour to each class
axes[1].contourf(GX, GY, pred_class, levels=[-0.5, 0.5, 1.5], colors=["C0", "C1"], alpha=0.25)
# Xc_train[Yc_train == 0]: indexing with a True/False tensor keeps the rows where the condition holds (shape (n, 2));
# .T turns it into two rows x and y, and * passes them as the two arguments of scatter
axes[1].scatter(*Xc_train[Yc_train == 0].T, s=5, color="C0", label="class 0")
axes[1].scatter(*Xc_train[Yc_train == 1].T, s=5, color="C1", label="class 1")
axes[1].set_aspect("equal"); axes[1].set_xlabel("$x$"); axes[1].set_ylabel("$y$"); axes[1].legend(loc="upper right")
axes[1].set_title("predicted class (background) and training data")
fig.tight_layout(); plt.show()

rng4 = np.random.default_rng(3)
x_s = np.sort(rng4.uniform(0, 1, 15))
y_s = np.sqrt(2) * np.sin(np.pi * x_s) + 0.05 * rng4.normal(size=15)
