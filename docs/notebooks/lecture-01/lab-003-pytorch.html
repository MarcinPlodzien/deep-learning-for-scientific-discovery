Lab 003 — PyTorch basics

PyTorch

A neural network can be evaluated with NumPy alone. Two things are missing for training it: the gradient of the loss with respect to the parameters, and speed for large problems. PyTorch provides three things:

  1. Tensors — arrays with (almost) the same interface as NumPy, which can also live on a GPU (graphics processing unit);
  2. Automatic differentiation — exact gradients of any computation built from tensor operations;
  3. Building blocks for networks — layers (torch.nn), loss functions and optimisers (torch.optim).

PyTorch, developed originally at Facebook AI Research (now Meta) and now governed by the PyTorch Foundation, is the most widely used deep-learning framework in research; Google’s JAX is its main alternative.

A two-line preview of point 2 gives the derivative \[\frac{d}{dx}\Big[\sin(x)\,e^{-x}\Big]_{x=1} = (\cos 1 - \sin 1)\,e^{-1} \tag{1}\] without deriving anything on paper:

x = torch.tensor(1.0, requires_grad=True)
(torch.sin(x) * torch.exp(-x)).backward();  print(x.grad)   # = (cos 1 - sin 1) e^{-1}

(It is run in Section 1.) The subject is point 1 and the forward part of point 3: how a network is built and evaluated.

We start with tensors themselves (Section 1) and their conversion to and from NumPy (Section 2), then look at the two kinds of hardware, CPU and GPU, on which they live (Section 3). Section 4 repeats the harmonic-oscillator calculation of the NumPy notebook with PyTorch’s linear algebra. Section 5 is a detailed tour of the operations that change the shape of tensors, ending with index notation and einsum. Sections 6 and 7 introduce layers, activation functions and model classes built on nn.Module. A summary (Section 8) and exercises with solutions (Section 9) close the notebook.

The notebook runs in Google Colab without any installation, in four simple moves: 1. Go to https://colab.research.google.com → File → Upload notebook (or open it from Google Drive). 2. Run cells one by one with Shift + Enter. Run them in order — later cells use variables defined earlier. 3. The required packages (numpy, matplotlib, torch) are pre-installed in Colab; no pip install required. 4. If the notebook state becomes inconsistent: Runtime → Restart session and run from the top.

1. Tensors

A torch.Tensor is PyTorch’s array. Almost every NumPy function has a PyTorch twin with the same name.

Code 
a = torch.tensor([1.0, 2.0, 3.0])
M = torch.tensor([[1, 2, 3], [4, 5, 6]])
print(a, a.shape, a.dtype)

tensor([[1, 2, 3],
        [4, 5, 6]]) torch.Size([2, 3]) torch.int64

a contains float32 numbers and M integers (int64): when no dtype is given, it is inferred from the Python numbers. Numbers with a decimal point give float32, PyTorch’s default floating-point type; numbers without a decimal point give int64. Inputs and weights of a network must be floating-point numbers, so data are entered as 1.0 rather than 1, or converted with .float().

The autograd preview of the introduction agrees with the analytic derivative \((\cos 1 - \sin 1)\,e^{-1}\): in double precision both give \(-0.11079376530669924\), identical in every printed digit.

Each operation of the table is performed once with NumPy and once with PyTorch. A PyTorch result is converted to NumPy with .numpy() and np.allclose(a, b) checks that all elements agree up to rounding errors: it tests \[|a - b| \le \text{atol} + \text{rtol}\,|b| \tag{2}\] element by element, with default tolerances atol of \(10^{-8}\) and rtol of \(10^{-5}\), so differences at the level of float64 rounding (about \(10^{-16}\)) are accepted.

Two functions used in the cell appear here for the first time. eigh (for symmetric matrices) returns the eigenvalues sorted in ascending order and the normalised eigenvectors as the columns of its second output: V[:, n] (all rows, column n) is the eigenvector belonging to E[n]. torch.outer(u, v) is the matrix with elements \(u_i v_j\) (Section 5.11), and all(... for n in range(3)) is True only if the comparison holds for every n = 0, 1, 2.

All operations agree, with two expected exceptions. The first concerns random numbers: NumPy and PyTorch have different random number generators, so the same seed gives different numbers. Both draw from the same normal distribution, so statistical results agree, but individual numbers do not. To use identical random data in both libraries, the data are created once (here in NumPy) and converted, as for x_np and x_t above. The second concerns eigenvectors: if \(v\) is a normalised eigenvector, so is \(-v\), and the two libraries may return different signs (the comparison of the raw eigenvectors may print False). The eigenvalues, the absolute values \(|v_i|\) and the projectors \(v v^{T}\) do not depend on this choice and agree.

Reproducibility within PyTorch is controlled by a random seed. torch.manual_seed(s) sets the starting point of PyTorch’s random number generator, so that the same “random” numbers are produced at every run of the notebook. The value of s is arbitrary: any integer gives a valid and reproducible sequence. Cells whose printed numbers are discussed in the text set their own seed (an arbitrary integer), so that these numbers do not depend on how many random numbers earlier cells used, or on the order in which the cells were run.

Floating-point precision

NumPy uses float64 by default, PyTorch float32. A float32 number takes 4 bytes instead of 8, and GPUs have many more arithmetic units for float32 than for float64; on GPUs float32 is therefore much faster and is standard in deep learning. Its relative rounding error of about \(10^{-7}\) is much smaller than the other errors of training a network (finite data, noisy gradients), so the lower precision does not limit the result. For precise physics calculations (e.g. diagonalising Hamiltonians, checking gradients) we switch to float64.

\(1/3\) is printed in both types with 17 digits, more than either type holds, so that the digit where each type departs from \(0.3333\dots\) is visible (the format :.17f means 17 digits after the decimal point). Machine epsilon (torch.finfo(dtype).eps) is the distance between 1 and the next representable number, i.e. the relative rounding error of the type: about \(1.2\times10^{-7}\) for float32 (about 7 significant digits) and about \(2.2\times10^{-16}\) for float64 (about 16 digits).

2. NumPy ↔︎ PyTorch

There are two ways to turn a NumPy array into a tensor, and they differ in an important detail. torch.from_numpy(arr) returns a tensor sharing memory with the NumPy array, so a change of one is visible in the other, while torch.tensor(arr) makes an independent copy. The way back is t.numpy(), which again shares memory. Matplotlib works with NumPy arrays and converts simple tensors automatically. For a tensor that takes part in gradient computations (requires_grad=True) both conversions fail; the conversion is then t.detach().numpy().

Code 
arr = np.arange(4.0)
t_shared = torch.from_numpy(arr)
t_copy = torch.tensor(arr)
arr[0] = 100.0
print("shared:", t_shared)       # changed as well
print("copy  :", t_copy)         # unchanged
print("dtype from NumPy:", t_shared.dtype, " <- float64 is kept")
shared: tensor([100.,   1.,   2.,   3.], dtype=torch.float64)
copy  : tensor([0., 1., 2., 3.], dtype=torch.float64)
dtype from NumPy: torch.float64  <- float64 is kept

A common error comes from mixing float64 (from NumPy) and float32 (model weights): passing a float64 tensor to a float32 layer gives RuntimeError: mat1 and mat2 must have the same dtype, but got Double and Float. The fix is torch.tensor(arr, dtype=torch.float32) or t.float(). (Element-wise operations such as a + b do not fail: the result is promoted to float64.)

3. CPU and GPU

A GPU (graphics processing unit, the processor of a graphics card) contains thousands of simple arithmetic units that work in parallel. It was built for computer graphics, and the same design suits the large matrix products of deep learning. The ordinary processor of the computer is the CPU (central processing unit). PyTorch addresses NVIDIA GPUs under the name "cuda" (CUDA, Compute Unified Device Architecture, is NVIDIA’s programming platform for its GPUs); torch.device("cuda") or torch.device("cpu") is an object naming the place where a tensor is stored and computed, and .cpu() returns the tensor in the memory of the CPU (a copy if it was on the GPU, the same tensor if it was already on the CPU).

In Colab: Runtime → Change runtime type → T4 GPU. Tensors are moved between devices with .to(device). All tensors taking part in one operation must be on the same device. The standard idiom, which works whether or not a GPU is present, is below. a if condition else b is a one-line if-statement whose value is a or b. The keyword device= of functions that create tensors places the new tensor directly in the memory of that device, without a copy from the CPU. The size \(2000\times2000\) is arbitrary.

Code 
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
print("using:", device)

A = torch.randn(2000, 2000, device=device)   # created directly on the device
B = A @ A                                    # computed on the device
B_cpu = B.cpu()                              # back to CPU (needed for .numpy() and plotting)
print(B.device, "->", B_cpu.device)
using: cpu
cpu -> cpu

The difference in speed is measured on a matrix product of size \(n\times n\) on the CPU (and on a GPU, if one is available). torch.cuda.synchronize() waits until the GPU has finished; otherwise the time would be measured too early.

time.perf_counter() returns the time of a high-resolution clock in seconds; the difference of two calls is the elapsed time, and the factor 1e3 converts it to milliseconds. The name _ is the usual Python name for a result that is computed but not used. The sizes are arbitrary: large enough for the computation to take longer than the overhead of a function call, small enough to finish in seconds. The product of two \(n\times n\) matrices needs about \(n^3\) multiplications (\(n^2\) output elements, each a sum of \(n\) products), so doubling \(n\) multiplies the work by 8. The measured times need not follow this factor exactly: the work is distributed over several CPU cores, which are used more efficiently for larger matrices, and other programs running at the same time disturb the measurement. Each time is averaged over 5 repetitions to reduce random fluctuations; the numbers change from run to run and from machine to machine.

Code 
import time

def time_matmul(n, device, repeats=5):
    A = torch.randn(n, n, device=device)
    _ = A @ A                                   # warm-up (first call has overheads)
    if device.type == "cuda": torch.cuda.synchronize()
    t0 = time.perf_counter()
    for _ in range(repeats):
        _ = A @ A
    if device.type == "cuda": torch.cuda.synchronize()   # GPU runs asynchronously: wait for it
    return (time.perf_counter() - t0) / repeats

for n in [500, 1000, 2000]:
    msg = f"n = {n:5d}: CPU {time_matmul(n, torch.device('cpu'))*1e3:8.2f} ms"
    if torch.cuda.is_available():
        msg += f" | GPU {time_matmul(n, torch.device('cuda'))*1e3:8.2f} ms"
    print(msg)

n =  1000: CPU     4.65 ms
n =  2000: CPU    41.95 ms

4. Linear algebra and the harmonic oscillator

As in the NumPy notebook, we discretise the harmonic oscillator on a grid with finite differences, but now we solve it with PyTorch, in float64. PyTorch can also differentiate through eigh, i.e. compute derivatives of eigenvalues with respect to parameters of the matrix.

In units in which \(\hbar\), \(m\) and \(\omega\) are 1 the Hamiltonian and its exact energies are \[H = -\frac12\,\frac{d^2}{dx^2} + \frac12 x^2, \qquad E_n = n + \tfrac12 . \tag{3}\] The second derivative is the three-point formula \[\psi''(x_i) \approx \frac{\psi_{i+1} - 2\psi_i + \psi_{i-1}}{\Delta x^2} , \tag{4}\] a tridiagonal matrix. The cell uses a few new functions. torch.diag(v, k) builds a square matrix with the vector v on the \(k\)-th diagonal (k = 1 directly above the main diagonal, k = -1 directly below, k = 0 or no k: the main diagonal); applied to a matrix instead of a vector, torch.diag does the opposite and extracts a diagonal. torch.eye(n) is the \(n\times n\) identity matrix, and x.numel() the number of elements of x. Finally, E[:5] are the five lowest levels, because eigh returns the eigenvalues in ascending order (and the eigenvectors as columns of psi).

The grid is chosen as follows. The low-lying eigenfunctions decay like \(e^{-x^2/2}\); at a distance 6 from the origin they are negligible (below \(10^{-4}\) of their maximum for the five lowest states). The matrix has no entries beyond the two ends of the grid, which is the same as requiring that \(\psi\) vanishes there (a box with hard walls at \(\pm 6\)). The error of the three-point formula decreases like \(\Delta x^2\): with 400 points (a spacing \(\Delta x\) of about 0.03) the first five energies are off by \(3\times10^{-5}\) (ground state) to \(1.2\times10^{-3}\) (fifth level); with 800 points these errors are four times smaller. Any grid with a few hundred points gives the picture shown below.

Code 
def hamiltonian_torch(x, V):
    """Finite-difference Hamiltonian -1/2 d^2/dx^2 + V on the uniform grid x (torch tensors)."""
    dx = x[1] - x[0]
    n = x.numel()
    ones = torch.ones(n - 1, dtype=x.dtype)
    kinetic = -0.5 / dx**2 * (torch.diag(ones, 1) - 2 * torch.eye(n, dtype=x.dtype) + torch.diag(ones, -1))
    return kinetic + torch.diag(V)

x = torch.linspace(-6, 6, 400, dtype=torch.float64)
E, psi = torch.linalg.eigh(hamiltonian_torch(x, 0.5 * x**2))
print("lowest energies:", E[:5])
lowest energies: tensor([0.5000, 1.4999, 2.4996, 3.4993, 4.4988], dtype=torch.float64)

5. Changing the shape of tensors

Shape operations are frequent in deep-learning code: a batch of images is flattened before a dense layer, a batch dimension is added to a single sample, the axes of an image are reordered for plotting, two tensors are joined along an axis. This section treats these operations one by one on small tensors whose entries are \(0, 1, 2, \dots\), so that the position of every number can be followed.

To make the result of each operation visible, a small helper draws a 2D tensor as a grid of coloured boxes. The colour of a box depends only on the number in it, so the same number has the same colour wherever it moves. np.ndenumerate(a) yields every index (i, j) together with the value a[i, j]; the format :g prints integers without a decimal point; the colour of the text switches from white to black above 60 % of the colour scale (a cosmetic choice) so that it stays readable on the light end of the ‘viridis’ colour map; and vmax or a.max() evaluates to a.max() when vmax is None.

Code 
def show_grid(t, title="", ax=None, vmax=None):
    """Draw a 1D or 2D tensor as a grid of boxes with the values stored in them."""
    a = t.detach().numpy()
    a = a.reshape(1, -1) if a.ndim == 1 else a
    if ax is None:
        fig, ax = plt.subplots(figsize=(0.6 * a.shape[1] + 0.6, 0.6 * a.shape[0] + 0.6))
    ax.imshow(a, cmap="viridis", vmin=0, vmax=vmax if vmax is not None else a.max())
    for (i, j), v in np.ndenumerate(a):
        ax.text(j, i, f"{v:g}", ha="center", va="center", color="white" if v < 0.6 * (vmax or a.max()) else "black")
    ax.set_xticks(range(a.shape[1])); ax.set_yticks(range(a.shape[0]))
    ax.set_title(f"{title}\nshape {tuple(t.shape)}", fontsize=10)
    return ax

5.2 Strides

In memory, the 12 numbers are always stored one after another in a single row. The shape only tells how to interpret this row. The strides say how many positions in memory one has to move to go to the next element along each dimension. For A = x12.reshape(3, 4) the strides are (4, 1): the next row starts 4 positions further, the next column 1 position further. The element A[i, j] is at memory position 4*i + 1*j. data_ptr() returns the memory address of the first element of a tensor; equal addresses mean that two tensors read the same memory.

Code

print("A and x12 share the same memory:", A.data_ptr() == x12.data_ptr())

5.3 Reordering axes

A.T (for 2D tensors), A.transpose(0, 1) and A.permute(1, 0) swap the two axes: row \(i\), column \(j\) of the result is element \((j, i)\) of A. No number is moved in memory: only the strides are swapped. The result is therefore again a view of the same memory, but its elements are no longer stored row by row; such a tensor is called non-contiguous.

5.4 Views and contiguity

t.view(shape) returns a new tensor object that uses the same memory as t. Only the description of how to read the memory (the shape and the strides) is new; not a single number is copied. Two consequences follow: creating a view is instantaneous, even for huge tensors, and changing an element through the view changes the original, and vice versa.

y = x12.view(3, 4) has the same memory address (data_ptr()) as x12, and a change of one element of y appears in x12.

Code

print("strides of y:", y.stride(), "-> element y[i, j] is at memory position 4*i + j")
print("same memory as x12:", y.data_ptr() == x12.data_ptr())

A common confusion is to take view(4, 3) for the transpose. Both x.view(4, 3) and x.T (for x of shape (3, 4)) have shape (4, 3), but they are different tensors. view keeps the order of the numbers in memory and only cuts the row of 12 numbers into pieces of 3; the transpose turns rows into columns.

Using view (or reshape) where a transpose is meant is a frequent bug: the shapes are right, the numbers are in the wrong places, and no error is raised.

The combination of view with a transpose shows when a view is impossible. A view must describe the requested shape with one stride per axis, i.e. along each axis the memory positions must be equally spaced. For x34.T (strides (1, 4)) this works. Now consider x34.T.view(-1), a flat tensor of 12 elements: reading x34.T row by row visits the memory positions shown below. They are not equally spaced (steps of \(+4, +4, -7, +4, \dots\)), so no single stride describes them, and view refuses. 5.9 Repeating values and broadcasting

expand repeats a tensor along axes of length 1 without copying (it sets the stride of these axes to 0); it can also add new axes in front, e.g. a vector of shape (W,) expanded to (H, W). repeat makes real copies. In arithmetic, broadcasting performs the expansion automatically. A typical use is the computation of all pairwise differences of \(N\) points in 2D. The points (N, 2) are turned into (N, 1, 2) and (1, N, 2); their difference broadcasts to (N, N, 2), with element diff[i, j] equal to the vector \(\mathbf p_i - \mathbf p_j\). diff.norm(dim=2) computes the length \(\sqrt{d_x^2 + d_y^2}\) of every such vector, i.e. along the last axis, so that dist[i, j] is the distance between points \(i\) and \(j\).

5.11 Tensors, indices and contractions

In this course a tensor is an array of numbers whose elements are labelled by indices: a scalar \(s\) has no index, a vector \(v_i\) one, a matrix \(A_{ij}\) two, a three-index array \(T_{ijk}\) three. Each index runs over one axis of the array; the range of an index is the length of that axis. A PyTorch tensor of shape (2, 3, 4) is \(T_{ijk}\) with \(i\) from 1 to 2, \(j\) from 1 to 3 and \(k\) from 1 to 4; in PyTorch the same indices run from 0, i.e. T[0..1, 0..2, 0..3]. The number of indices is called the rank (or order) of the tensor; this is not the rank of a matrix in linear algebra. In PyTorch it is t.ndim.

The simplest product of two vectors is the inner (scalar) product. For two vectors \(u\) and \(v\) of the same length \(m\), \[s = \sum_{i=1}^{m} u_i\, v_i, \qquad (m)\cdot(m) \;\to\; \text{a scalar}. \tag{7}\] The two vectors share the index \(i\), which is summed: nothing is left, and the result is a single number. Both vectors must have the same length, because they share the index. This is the simplest contraction, and the two products below are built from it.

A matrix acts on a vector in the same way. For a matrix \(A\) of shape \(n\times m\) and a vector \(v\) of length \(m\), \[w_i = \sum_{j=1}^{m} A_{ij}\, v_j, \qquad i = 1, \dots, n . \tag{8}\] Element \(w_i\) is the scalar product of row \(i\) of \(A\) with \(v\). The summed index \(j\) belongs to both factors and must therefore have the same range in both: the number of columns of \(A\) must equal the length of \(v\). The result keeps the free index \(i\): \[(n\times m)\cdot(m) \;\to\; (n). \tag{9}\]

The product of two matrices follows the same pattern. For \(A\) of shape \(n\times m\) and \(B\) of shape \(m\times p\), \[C_{ik} = \sum_{j=1}^{m} A_{ij}\, B_{jk}, \qquad (n\times m)\cdot(m\times p) \;\to\; (n\times p). \tag{10}\] Element \(C_{ik}\) is the scalar product of row \(i\) of \(A\) with column \(k\) of \(B\). The “inner” dimensions (both \(m\)) are summed and disappear; the “outer” ones (\(n\) and \(p\)) remain. The matrices need not be square: only the summed index must match. In general the products \(AB\) and \(BA\) differ, even for square matrices; for rectangular matrices \(BA\) may not even be defined (it requires as many columns of \(B\) as rows of \(A\)).

The opposite case is the outer product. If no index is summed, two vectors give a matrix, \[M_{ij} = u_i v_j , \qquad (n)\cdot(m) \;\to\; (n\times m), \tag{11}\] and the vectors may have different lengths.

The matrix-vector and matrix-matrix products are the simplest examples of one general operation, the tensor contraction. A contraction sums over a pair of indices with the same range: one index from each of two tensors (as \(j\) above), or two indices of the same tensor (as in the trace of a matrix). Each contracted pair removes two indices, so \[\text{rank of the result} = \text{sum of the ranks of the factors} - 2\times(\text{number of contracted pairs}). \tag{12}\] This rule holds when every index either appears once (a free index) or appears exactly twice and is summed. An index that is shared but not summed (a batch index, or an element-wise product, see 5.12) lowers the rank by one instead of two. For the products above, \[\begin{aligned} &\text{inner product: } 1 + 1 - 2 = 0 \ \text{(a scalar)}, && \text{matrix times vector: } 2 + 1 - 2 = 1, \\ &\text{matrix times matrix: } 2 + 2 - 2 = 2, && \text{outer product: } 1 + 1 - 0 = 2 . \end{aligned} \tag{13}\] With more indices the same operation reads, for example, \[C_{il} = \sum_{j}\sum_{k} T_{ijk}\, S_{jkl}, \qquad (n\times m\times r)\cdot(m\times r\times p)\;\to\;(n\times p),\qquad \text{rank } 3 + 3 - 4 = 2 , \tag{14}\] two pairs of indices (\(j\) and \(k\)) being contracted at once. Contractions of this kind are common in physics: the expectation value \[\langle\psi|H|\psi\rangle = \sum_{ij}\psi_i^* H_{ij}\psi_j , \tag{15}\] the stress tensor acting on a normal vector, tensor-network states of quantum many-body systems.

Because sums over repeated indices are so frequent, Einstein proposed to omit the summation sign: in the Einstein summation convention an index that appears twice in a product is summed. The formulas above become \[w_i = A_{ij}v_j, \qquad C_{ik} = A_{ij}B_{jk}, \qquad s = u_iv_i, \qquad C_{il} = T_{ijk}S_{jkl} . \tag{16}\] Indices that appear once (here \(i\), \(k\), \(l\)) are free: they label the elements of the result.

5.12 einsum

torch.einsum takes such a formula as a string and is the summation convention in code. For the matrix product \(C_{ik}\) of equation (16) one writes

C = torch.einsum("ij,jk->ik", A, B)

The string is read with three rules. First, left of -> there is one group of letters per input tensor, separated by commas, with one letter per axis. "ij,jk" says that the first tensor has two axes called i and j, and the second two axes called j and k; the number of letters must equal the number of axes of the tensor. Second, the same letter in different inputs means that these axes are the same index: they must have equal lengths, and the elements are multiplied with matching values of this index. Third, right of -> stand the free indices of the result, in this order. Every letter that appears on the left but not on the right is summed over. Unlike in the pure Einstein convention, the output is given explicitly; this also allows keeping a repeated index (no sum) or choosing the order of the axes.

In words, "ij,jk->ik" means: for every pair \((i, k)\), multiply \(A_{ij}B_{jk}\) and sum over \(j\), because \(j\) does not appear in the output.

The rules can be checked by computing the same quantity with explicit loops: one loop per letter, the product of the indexed elements in the innermost loop, and accumulation into the output elements labelled by the letters after ->. The comparisons use torch.allclose(a, b), which checks equality up to the rounding errors of floating-point arithmetic: element by element it applies the test of equation (2), with the same default tolerances. In float32 a sum computed in a different order (loops, @, einsum) differs in the last digits, i.e. by about \(10^{-7}\) times the size of the terms. For elements that happen to be close to zero the relative part \(\text{rtol}\,|b|\) is then tiny and the default \(\text{atol}\) can be too strict, so several later cells set atol=1e-6 (or 1e-5 for larger sums) as a safeguard against such false alarms.

Code 
torch.manual_seed(1)
a = torch.randn(2, 3)          # axes i (length 2), j (length 3)

Expectation values in quantum mechanics are a natural physics application. For a state vector \(\psi\) (normalised, real here for simplicity) and a Hamiltonian matrix \(H\), equation (15) with real components, \[\langle\psi|H|\psi\rangle = \sum_{ij}\psi_i H_{ij}\psi_j , \tag{17}\] is "i,ij,j->": three inputs, all letters summed. For a batch of states \(\psi_{bi}\) the batch letter is kept: "bi,ij,bj->b" gives one expectation value per state. We use the grid Hamiltonian of the harmonic oscillator from Section 4 and its first three eigenstates, whose energies are about 0.5, 1.5 and 2.5. Since eigh returns normalised eigenvectors, \[H\psi_b = E_b\psi_b, \qquad \sum_i \psi_{bi}^2 = 1 , \tag{18}\] the expectation values must equal the eigenvalues. eigh returns the eigenvectors as the columns of psi_ho, so psi_ho[:, :3] holds the three lowest states as columns and the transpose .T puts them into rows, one state per value of b.

An einsum string never contains the lengths of the axes: "ij,jk->ik" works for matrices of any sizes \(n\times m\) and \(m\times p\). What a string fixes is the number of axes of every input. Two tools handle tensors whose number of axes is not known beforehand.

The first is the ellipsis ..., which stands for “any number of axes here, possibly none”. The letters then describe only the axes that take part in the operation, and all other axes are carried along unchanged. The string "...i,ji->...j" applies a matrix \(W_{ji}\) to the last axis of a tensor of any rank, e.g. shapes (4,), (B, 4) or (B, T, 4); this is what nn.Linear does with its input (apart from adding the bias). Similarly, "...ij,...jk->...ik" gives matrix products with any number of batch axes in front, and "...ii->..." the trace over the last two axes, whatever comes before them.

The comparisons in the cell address axes with negative numbers, which count from the end: \(-1\) is the last axis, \(-2\) the one before it. This addresses the last axes independently of how many axes stand in front of them, the same idea as .... Sq.diagonal(dim1=-2, dim2=-1) takes the diagonals of the matrices formed by the last two axes, and .sum(-1) sums over the last axis. (In reshape and view, by contrast, \(-1\) means “size to be computed”.)

The second tool is to build the string in code. Sometimes the axis that takes part in the contraction is only known when the program runs, e.g. “apply the matrix \(M\) to axis \(k\) of a tensor \(T\) with \(N\) axes”, where \(N\) and \(k\) are variables. The string is then assembled from letters: one letter per axis of \(T\), the letter of axis \(k\) is shared with \(M\), and in the output it is replaced by a new letter: \[T'_{a_1 \dots a_{k-1}\, b\, a_{k+1} \dots a_N} = \sum_{a_k} M_{b\, a_k}\, T_{a_1 \dots a_k \dots a_N}. \tag{19}\] This operation appears, for example, when an operator acts on one index of a many-index object (in quantum mechanics: a one-qubit gate acting on the state of \(N\) qubits, stored as a tensor with \(N\) axes of length 2).

The cell uses a few Python details: the module string provides string.ascii_lowercase, the string 'abcdefghijklmnopqrstuvwxyz'; a string is sliced like a list (letters[:4] is 'abcd'); f"..." inserts the values of the expressions in braces; and a function can return several values separated by commas, which the caller unpacks into several variables (out, spec = ...).

Code 
import string

def apply_along_axis(M, T, k):
    """Contract the matrix M (shape (n_out, n_k)) with axis k of the tensor T; the new axis stays at position k."""
    letters = string.ascii_lowercase                 # 'abcdefghijklmnopqrstuvwxyz'
    t_idx = letters[:T.ndim]                         # one letter per axis of T, e.g. 'abcd'
    new = letters[T.ndim]                            # an unused letter for the output axis
    out_idx = t_idx[:k] + new + t_idx[k + 1:]        # axis k replaced by the new letter
    spec = f"{new}{t_idx[k]},{t_idx}->{out_idx}"     # e.g. 'ec,abcd->abed' for k = 2
    return torch.einsum(spec, M, T), spec

# check: move axis k to the end, multiply with M^T, move the new axis back to position k

movedim(source, destination) moves one axis to another position (a permute that changes only one axis). The same contraction can also be done with torch.tensordot(M, T, dims=([1], [k])), which contracts axis 1 of M with axis k of T and puts the remaining axes of M first; einsum has the advantage that the order of the output axes is written explicitly.

To sum up the rules of einsum: one letter per axis; equal letters are the same index; letters missing after -> are summed; letters kept after -> are not summed (if they appear in several inputs they act as batch indices); the order of the letters after -> is the order of the output axes. ... stands for any number of further axes, so that one string works for tensors of different rank; strings can also be assembled in code. When an operation has a standard function (@, .T, sum), that function is usually at least as fast; einsum is most useful when several axes are contracted at once or when the index notation makes the code easier to compare with a formula.

6. Layers and activation functions

nn.Linear(n_in, n_out) is the dense (fully connected) layer \[\mathbf z \;\mapsto\; \mathbf W\mathbf z + \mathbf b . \tag{20}\] It creates and randomly initialises its own parameters weight (shape (n_out, n_in)) and bias (shape (n_out,)): by default all of them are drawn uniformly from \([-1/\sqrt{n_{\rm in}},\, 1/\sqrt{n_{\rm in}}]\). The factor \(1/\sqrt{n_{\rm in}}\) keeps the outputs of the layer of order one, independently of the number of inputs (the reason is given in Section 7). The input is a batch of shape (B, n_in), and the output has shape (B, n_out).

In the printout, .data gives the bare numbers of a parameter without its gradient bookkeeping; it is used here only for a shorter printout. In computations .data should be avoided, because changes made through it are invisible to autograd; the safe alternatives are .detach() and torch.no_grad().

The single-hidden-layer network \[f(x) = \sum_{i=1}^{N} W^{(2)}_i\,\sigma(W^{(1)}_i x + b_i) + b^{(2)} , \tag{21}\] with \(\tanh\) as \(\sigma\), is Linear(1, N) → Tanh → Linear(N, 1). Drawing and summarising a network

The structure of the network above can be shown in three complementary ways: by our own drawing function, which shows every neuron and every weight, and by the libraries torchinfo and torchview, which work on the level of layers and accept any PyTorch model.

draw_network is the drawing function used for network diagrams throughout the course. It draws a dense network as columns of circles, one column per layer and one circle per neuron, and joins every circle with every circle of the next column by a thin grey line, one line per weight. The height of a column grows with the logarithm of the layer size, so that a wide layer looks taller than a narrow one and a network that compresses its input visibly narrows. A layer with more neurons than max_nodes is drawn with its first and last few neurons and a vertical ellipsis in between; its true size is always written under the column. The colours follow one convention in all notebooks: grey for the data at the input and at the output, blue for hidden layers, orange for a latent (bottleneck) layer and green for an additional input such as a class label.

To draw your own network, pass the list of layer sizes from the input to the output, for example draw_network([784, 128, 64, 10]), and, if you wish, a list of names (labels) and of colours (colors) with one entry per column. An entry of layer_sizes can itself be a list, such as [16, 16], which stacks two blocks in one column; groups draws a bracket with a name above a range of columns, and no_input lists blocks that receive no edges from the previous column. The function returns the matplotlib axes, so the figure can be changed further or saved with ax.figure.savefig(...). It needs only NumPy and matplotlib and therefore also runs in Colab. The comments in the code explain each step (node positions, the truncation of large layers, the edges, the labels and the brackets), so that the function can be adapted to other diagrams.

def draw_network(layer_sizes, labels=None, colors=None, max_nodes=10,
                 groups=None, no_input=None, ax=None, node_radius=0.11,
                 x_gap=1.6, min_height=1.0, height_scale=1.1, fontsize=13):
    """Draw a fully connected network as columns of circles joined by edges.

    Parameters
    ----------
    layer_sizes : list
        One entry per column, from the input to the output. An entry is
        either an int (the number of neurons of one layer) or a list of ints
        (several blocks stacked in the same column, e.g. [16, 16] for the mean
        and the log-variance of a variational autoencoder, or [784, 10] for an
        image together with a one-hot condition).
    labels : list, optional
        Names shown under each column next to the true layer size. An entry
        may be None (size only), a string, or, for a stacked column, a list
        with one string per block.
    colors : list, optional
        Fill colour of the nodes of each column (or a list with one colour per
        block). By default the first and the last column are grey and all
        others blue.
    max_nodes : int
        Largest number of circles drawn for one block. A larger block is shown
        by its first and last few nodes with a vertical ellipsis in between;
        the true size is always shown in the label.
    groups : list of (text, first_column, last_column), optional
        Brackets drawn above a range of columns, e.g. ("encoder", 0, 2).
    no_input : list of (column, block), optional
        Blocks that receive no edges from the previous column, e.g. a condition
        c that enters the decoder from outside.
    ax : matplotlib Axes, optional
        Axes to draw into; a new figure is created when None.
    node_radius, x_gap : float
        Radius of a circle and horizontal distance between columns.
    min_height, height_scale : float
        The height of a block of size s is min_height + height_scale*log10(s),
        so that a narrow layer is visibly shorter than a wide one.
    fontsize : int
        Font size of all labels.

    Returns
    -------
    ax : the matplotlib Axes with the drawing.
    """
    n = len(layer_sizes)
    # Turn every entry into a list of blocks, so that a plain layer is a
    # column with a single block.
    blocks = [s if isinstance(s, (list, tuple)) else [s] for s in layer_sizes]
    if labels is None:
        labels = [None] * n
    if colors is None:
        colors = [GREY] + [BLUE] * (n - 2) + [GREY]
    no_input = set(no_input or [])

    def per_block(value, k):
        # Repeat a single value for all k blocks of a column, or keep a list.
        return list(value) if isinstance(value, (list, tuple)) else [value] * k

    if ax is None:
        _, ax = plt.subplots(figsize=(1.9 * n + 1, 5.5))

    # ---- Node positions ---------------------------------------------------
    # Column i sits at x = i * x_gap. Inside a column the blocks are stacked
    # from top to bottom with a small gap, and the whole column is centred
    # on y = 0. Each block gets a height that grows with log10 of its size
    # (but is never too small for its circles to fit without overlapping);
    # the drawn nodes are spread evenly over that height.
    nodes = []            # nodes[i][b] = list of (x, y) of block b in column i
    tops, bottoms = [], []
    gap = 0.9             # vertical space between stacked blocks (holds a label)
    for i, blk in enumerate(blocks):
        cols = per_block(colors[i], len(blk))
        labs = per_block(labels[i], len(blk))
        heights = [max(min_height + height_scale * np.log10(s),
                       (min(s, max_nodes) - 1) * 2.3 * node_radius) for s in blk]
        total = sum(heights) + gap * (len(blk) - 1)
        x, y_top = i * x_gap, total / 2
        column = []
        for s, h, c, lab in zip(blk, heights, cols, labs):
            shown = min(s, max_nodes)
            if s <= max_nodes:
                # Small block: draw every neuron.
                ys = np.linspace(y_top, y_top - h, shown) if shown > 1 else np.array([y_top - h / 2])
            else:
                # ---- Truncation of large layers ----------------------------
                # Draw max_nodes circles: half in the upper 38 % of the block,
                # half in the lower 38 %, and a vertical ellipsis in the
                # middle to show that neurons are omitted.
                k = max_nodes // 2
                ys = np.concatenate([np.linspace(y_top, y_top - 0.38 * h, k),
                                     np.linspace(y_top - 0.62 * h, y_top - h, max_nodes - k)])
                ax.text(x, y_top - 0.5 * h, r"$\vdots$", ha="center", va="center",
                        fontsize=fontsize + 6, color=c, zorder=4)
            for y in ys:
                ax.add_patch(Circle((x, y), node_radius, facecolor=c,
                                    edgecolor="black", lw=0.6, zorder=3))
            column.append([(x, y) for y in ys])

            # ---- Labels of stacked blocks ----------------------------------
            # In a column with several blocks each block is labelled just
            # below its last node, in its own colour, on a white box so that
            # the edges behind do not hide the text.
            if len(blk) > 1:
                text = f"{s}" if lab is None else f"{lab} {s}"
                ax.text(x, y_top - h - 0.2, text, ha="center", va="top",
                        fontsize=fontsize - 1, color=c, zorder=5,
                        bbox=dict(facecolor="white", edgecolor="none", pad=0.5))
            y_top -= h + gap

        # ---- Label of a single-block column: name and true size below ----
        if len(blk) == 1:
            lab = labs[0]
            text = f"{blk[0]}" if lab is None else f"{lab}\n{blk[0]}"
            ax.text(x, -total / 2 - 0.3, text, ha="center", va="top", fontsize=fontsize)
        nodes.append(column)
        tops.append(total / 2)
        bottoms.append(-total / 2)

    # ---- Edges ---------------------------------------------------------------
    # A dense layer connects every neuron of one column with every neuron of
    # the next, so we draw a thin grey line for every pair of drawn nodes,
    # skipping the blocks listed in no_input. zorder=1 keeps lines behind
    # the circles.
    for i in range(n - 1):
        sources = [p for block in nodes[i] for p in block]
        for b, block in enumerate(nodes[i + 1]):
            if (i + 1, b) in no_input:
                continue
            for (x0, y0) in sources:
                for (x1, y1) in block:
                    ax.plot([x0, x1], [y0, y1], color="#B0B0B0", lw=0.35, zorder=1)

    # ---- Group brackets ------------------------------------------------------
    # A bracket above columns first..last with its text, e.g. "encoder".
    y_br = max(tops) + 0.45
    for text, i0, i1 in (groups or []):
        x0, x1 = i0 * x_gap - 0.3, i1 * x_gap + 0.3
        ax.plot([x0, x0, x1, x1], [y_br - 0.12, y_br, y_br, y_br - 0.12],
                color="black", lw=1.2)
        ax.text((x0 + x1) / 2, y_br + 0.1, text, ha="center", va="bottom",
                fontsize=fontsize)

    # ---- Axes limits ----------------------------------------------------------
    # Leave room for the brackets above and the labels below.
    ax.set_xlim(-0.8, (n - 1) * x_gap + 0.8)
    ax.set_ylim(min(bottoms) - 1.3, y_br + (0.7 if groups else 0.2))
    ax.set_aspect("equal")
    ax.axis("off")
    return ax

7. Model classes

For anything non-trivial we define a class that inherits from nn.Module. Two methods are required. __init__ creates the layers and parameters, and must always call super().__init__() first. forward(x) describes the computation; the model is then called as model(x), not model.forward(x). Parameters wrapped in nn.Parameter (and all parameters of sub-layers) are registered automatically.

Both rules have a reason. super().__init__() runs the __init__ of nn.Module, which creates the internal lists in which parameters and sub-layers are registered; assigning an nn.Parameter before this call fails with AttributeError: cannot assign parameters before Module.__init__() call. Calling model(x) runs forward together with additional bookkeeping of PyTorch (so-called hooks), which a direct call of forward would skip.

Below, the Universal Approximation Theorem (UAT) ansatz is implemented explicitly — exactly the formula from the lecture. In def __init__(self, N, activation=torch.tanh) the argument activation has a default value: it is used when the caller does not give this argument. A function such as torch.tanh can be passed and stored like any other object.

The initial values are chosen as follows. W1 and b are drawn from the standard normal distribution. Neuron \(i\) switches (its \(\tanh\) changes sign) at \[x_i^\ast = -b_i/W^{(1)}_i ; \tag{23}\] with W1 and b of order one, most of these points (about 80 %) lie in \([-3, 3]\), the range of inputs of the plots, so most neurons are not saturated there. The output bias c (\(b^{(2)}\) above) only shifts \(f\) up or down; there is no reason to start with a shift, so it starts at 0.

Code 
class UATNet(nn.Module):
    """f(x) = sum_i W2_i * sigma(W1_i * x + b_i) + c   (single hidden layer, N neurons)."""

    def __init__(self, N, activation=torch.tanh):
        super().__init__()
        self.W1 = nn.Parameter(torch.randn(N))        # input weights
        self.b = nn.Parameter(torch.randn(N))         # biases
        self.W2 = nn.Parameter(torch.randn(N) / N**0.5)  # output weights, scaled by 1/sqrt(N) (explained below)
        self.c = nn.Parameter(torch.zeros(1))         # output bias
        self.activation = activation

    def forward(self, x):                             # x: shape (B,) -> output (B,)
        hidden = self.activation(self.W1 * x[:, None] + self.b)   # (B, N) by broadcasting
        return hidden @ self.W2 + self.c

The output weights are divided by \(\sqrt N\), and the reason is statistical. The output is a sum of \(N\) terms, \[f(x) = \sum_{i=1}^{N} W^{(2)}_i h_i(x) + c, \qquad h_i = \tanh(\dots)\in[-1,1] . \tag{24}\] If the \(W^{(2)}_i\) are independent random numbers with mean 0 and variance \(\sigma_W^2\), the terms are uncorrelated with mean zero and their variances add: \[\mathrm{Var}\, f(x) = N\,\sigma_W^2\,\overline{h^2}, \qquad \text{standard deviation of } f \;\propto\; \sqrt{N}\,\sigma_W , \tag{25}\] where \[\overline{h^2} = \frac1N\sum_i h_i(x)^2 \le 1 \tag{26}\] is the mean squared hidden activation (the variance is taken over random \(W^{(2)}\) at fixed \(x\), with vanishing \(c\)). With unit \(\sigma_W\) an untrained network with many neurons would produce outputs that grow like \(\sqrt N\), far from the order-one values of typical targets. With \(\sigma_W\) of \(1/\sqrt N\) the variance of the output is of order one for every \(N\). The same rule, weights scaled by \(1/\sqrt{n_{\rm in}}\) with \(n_{\rm in}\) the number of inputs of the layer, is the basis of the standard initialisations (LeCun, Xavier/Glorot), and nn.Linear uses it by default. The first layer has a single input, so W1 is not scaled. The standard deviation of \(f\) over the inputs and 50 random initialisations is measured with and without the factor; the 50 outputs of shape (200,) are joined by torch.cat into one vector of 10 000 values, of which std() computes the sample standard deviation (normalised by the number of values minus one, which makes no difference for 10 000 values).

8. Summary

Tensors are NumPy arrays with two additions, GPU support and automatic differentiation. Their default dtype is float32; float64 is used for precise physics. torch.from_numpy shares memory with a NumPy array while torch.tensor copies it, and .numpy(), .item() and .cpu() lead back. Among the shape operations, reshape and view change the shape while keeping the row-by-row order, transpose and permute reorder axes (producing non-contiguous views), unsqueeze and squeeze add or remove axes of length 1, cat joins along an existing axis and stack along a new one; batched products are computed with @ or einsum. The device is chosen with device = "cuda" if available else "cpu", and all tensors in one operation must be on the same device. nn.Linear(n_in, n_out) computes \(\mathbf W\mathbf z+\mathbf b\) on batches (B, n_in), nn.Sequential stacks layers, and our own models subclass nn.Module with __init__ and forward. When a network is only evaluated, the computation goes inside with torch.no_grad():.

    weight_std_factor=None: PyTorch default initialisation; otherwise weights ~ N(0, (factor/sqrt(n_in))^2)."""

Write an nn.Module called GaussianRBF implementing \[f(x) = \sum_{i=1}^{N} a_i\, \exp\!\big(-(x-\mu_i)^2 / (2 s_i^2)\big) \tag{30}\] with trainable \(a_i, \mu_i, s_i\) (nn.Parameter). Solution

class GaussianRBF(nn.Module):
    """f(x) = sum_i a_i exp(-(x - mu_i)^2 / (2 s_i^2)) with trainable a, mu, s."""

    def __init__(self, N):
        super().__init__()
        # nn.Parameter registers the tensor as a trainable parameter of the module
        self.a = nn.Parameter(torch.randn(N))                 # amplitudes
        self.mu = nn.Parameter(torch.linspace(-3, 3, N))      # centres on a uniform grid
        self.s = nn.Parameter(0.5 * torch.ones(N))            # widths; for N = 6 the centres are 1.2 apart, so neighbouring
                                                              # Gaussians of width 0.5 overlap and their sum is a smooth curve

    def basis(self, x):
        """The N Gaussians evaluated at all points: shape (B, N)."""
        return torch.exp(-(x[:, None] - self.mu)**2 / (2 * self.s**2))

    def forward(self, x):
        return self.basis(x) @ self.a                         # weighted sum -> shape (B,)
